# Building-loop 0.7.39 更新说明

**待审核时自动派发。** 初稿等首审、修订稿等终审时，宿主确认项目已就绪且相关会话空闲后，自动派出对应的独立审核会话。遇到需要你决定的事项，会等你回复后再继续。Windows 意外退出后，恢复原会话即可按原审核者和交接编号继续。 [正式桌面验收](../experiments/results-0.7.39-unattended-handoff.md)

## 这次更新了什么

- **修复首审和终审漏派。** 0.7.38 中能复现两个待审核阶段停住。0.7.39 会补派，沿用原有签名、架构、资料来源和独立审核门槛。验证终审时，空证明被拒，独立证明齐全后才进入账本复盘。
- **保留真正的用户等待。** 需要澄清指标，或原生会话正在问用户时，即使总控空闲也会继续等待。原生入口收到明确答复后，任务可自动恢复。
- **强退恢复沿用原派单。** 分别在待派状态落盘、审核者已预留但尚未收件、审核者已经收件三个时点强制结束 Windows DSH 宿主。恢复原会话后，同一交接均只有一条派单。已经收件的审核者仍能读原文并提交退回。 [原生验收数据](../experiments/observations-0.7.39-unattended-handoff-native.json)

Windows 全套回归 **496/496**，定点及关联回归 **27/27**。隔离安装逐文件核对 **59/59**。正式 Desktop Profile 由 0.7.35 更新到 0.7.39，重启后插件详情显示 v0.7.39，新会话能选择 building-loop。强退复验使用实际 Windows DSH 宿主与本地确定性响应，外部模型调用为 **0**。 [完整记录](../experiments/results-0.7.39-unattended-handoff.md) · [稳定版工程与资料实测](../experiments/showcase-0.7.39.md#当前稳定版0739-自身复验)

兼容基线为 DeepSeek Harness `0.2.2-rc.1` 和 DSH NEXT `2.0.22-next`。正式桌面验证了安装和重启，强退复验在隔离的 Windows DSH 环境完成。审核自动接力仍要求任务已到待审核阶段、当前目标和材料有效、没有待处理的问答或批准。结论的证据范围与推理质量仍由独立审核判断。 [审核与证据规则](../governance/verification.md)

## 安装或更新

在 Windows Desktop 侧栏打开 **插件 → 添加插件**，选择指定版本的安装包或仓库来源。管理 Desktop 需要使用 DSH NEXT 打开的内置终端及目标 `desktop` Profile。Web Profile 有独立安装入口。更新后重新打开 DSH 并核对插件详情，在新会话的模式列表选 **building-loop**。如从旧包 `building-loop` 迁移，先在同一个 Profile 移除旧包，再安装 `dsh-building-loop`。 [安装步骤](../README.md#安装)

本仓库当前稳定基线为 **0.7.39**。运行时代码固定于 `f4cadfe86e603ca17375e85036bd51295542386c`，正式部署记录归档于 `91260085449537af43f4a1e0741c16f4c1f29d8f`，当时验收安装包的 SHA-256 为 `65e39183266aa4d5623a80cac03af38c0e421dcc42da46164e6845ffd7b59ee1`。0.7.40 和 0.7.41 归档为对照实验，发布状态为未放行。
