# 0.6.0 全文覆盖与逐条推导：真实 DeepSeek 验收

上级为[实验索引](README.md)。机制与有限保证见[全文覆盖](../governance/full-coverage.md)。本报告区分宿主流程通过、指定样例通过和人工核对成稿，不能用关单标签代替语义正确。

## 条件和样例

通过 DSH `0.2.2-rc.1` 的真实 `deepseek-official/deepseek-flash` 路由调用，运行时列表显示 `DeepSeek-V4.1-Flash`；thinking 关闭、单次输出上限 4096、每轮 900 秒／300 步。每轮启动隔离 Profile，使用实际生产工具处理函数。复用和新开只改变 `continuation`；最终两组使用同一份运行模块字节。两组时间有重叠，服务端缓存与随机输出未被控制，因此结果不是严格因果实验。

材料是当次实际取得的 GitHub Checks 和 NIST Scatter Plot 官方短摘录，以及明确标注的合成记录。没有把合成观测说成真实研究。取得时间、HTTP 状态、页面摘要、摘录摘要与逐字核对记录随每轮归档；实验子会话读冻结材料，没有自行联网搜索。来源凭据说明版本和取得过程，不证明任意网页的全部结论。

三个错误位于普通说明段：completed→必定成功；正相关→干预必然提高每个人分数；A→复核被倒转为复核→A。最终七个正确对照涵盖官方直接转述、有效规则推导、谨慎的相关性判断、明确假设、大白话阅读建议，以及明确标注的错误示例。期望结果单独封存，不在任何模型的读白名单里。首次调试的第九项大白话对照是事后发现后新增的观察；原始八项清单没有被修改。最终两组使用 v2 夹具，增加显式错误示例并把行内引文位置留在句号之前；这两组相互可比，但不能把跨调试版本的用量变化归因于某一个修复。

首轮核验后，维护者把交互看板目标改为中文说明文档，检查取消动画与测验、覆盖 FAQ、保留来源链接复核。阶段、读写、真实子会话身份、完整记录与所有已返回用量均从原始事件重算。

## 可确认与不能外推的内容

程序强制了全文记录、原文位置和引句、有限推导规则、反例状态、当前版本绑定、独立复核与账本闭环。自然语言的概念映射、隐含前提与来源上游真实性仍需要语义核验；同源模型的两个会话可能共同出错，本批失败已直接证明这一点。46 项回归和少量真实样例不能给出普遍正确率。

引用匹配只覆盖明确标为原文／原句／逐字引文且同行有来源行号的格式；其他引用样式和隐含推理继续列为后续改进范围。小任务的批次提交、核验往返和保留全部上下文仍可能昂贵，不能从缓存命中高推断总 Token 少。后续优化见[本项目账本](../docs/task-ledger.md)。

最终新开稿还保留一个格式差异：“大白话”之后有一条明确错例，严格说并非最后一段。终审与总控都记录了这个差异。本报告的通过范围是本次指定的事实／推导对照与账本流程，不能扩写成所有质量要求已完美通过。NIST 摘录头部还沿用了 GitHub 列表说明的模板文字；实际 NIST 引句和其行号无误，该原始材料瑕疵也保留在归档中。

大白话：现在每处内容都得留下核验记录，每条显式推导都得交代凭什么，流程也会换一个会话再查；这次测到了哪些问题、花了多少、哪里失败过，都公开留着。它增加了能执行的关口，没有把“模型说通过”包装成绝对真实。
