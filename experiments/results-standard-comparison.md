# 标准模式与 Building-loop 0.7.14 配对实测

上级为[实验索引](README.md)。这轮单独回答在同一任务下标准模式和 Building-loop 各交付了什么。历史上 Building-loop 复用／新开、旧／新版和 API 历史阈值实验用于解释机制边界，不进入本轮两模式的分数或用量。

## 对照口径

- 使用实际安装的 Windows DSH 宿主、同一个 DeepSeek Flash 模型和同一组模式设置。每个题目两边获得相同的人类输入和资料；评分条件在发送前确定。使用各模式自己的提示词、工具、状态和交付路径，这些正是需要对照的差异。
- **内容质量**比较两边实际交付的文本或文件，草稿可以评分但必须标明未验收。**流程能力**单独记录是否有持久任务状态、原文凭据、独立审核、账本和关单。普通模式本来无需满足 Building-loop 的关单条件；也不能因为 Building-loop 生成了回执就额外给它内容分。
- **用量**取原生助手事件。缓存命中率分母为全部提示词输入，已知总量含未缓存输入、缓存读取和输出。未返回的用量保持未知。小样没有随机化或足够重复，缓存状态与顺序可能影响开销，不能估计一般任务的胜率、费用或最优换会话阈值。

## 新跑的两组同题对照

| 同题场景 | DSH 标准模式 | Building-loop 0.7.14 |
|---|---|---|
| 证据核对：S9 缺源、24%／24 ms、相关当因果、正确样本比例及末段行动建议 | 完成，5/5。3.506 秒，10,104 Token，缓存读取 9,216，命中率 93.73%。 | 2/5，停在首审，175.381 秒内未关单。1,139,597 Token，缓存读取 1,086,592，命中率 97.22%。项目保留 E1/E2，但实际送给子会话的直接开工原文在 C1 句中截断，缺少 C2–C4，执行方报告缺项。 |
| 工程规划：结算 API／Worker／Release，开工前从全量发布改为仅预发布演练 | 26.227 秒完成并写出计划。8 项中 5 完全符合、2 部分符合、1 不符合。59,784 Token，缓存读取 54,400，命中率 96.01%。 | 写出稿件并保留 A1–A4 的会话事件与逐字摘录摘要。8 项中 4 完全符合、3 部分符合、1 不符合。205.124 秒终点仍在首审，持久覆盖 108/125，无独立反证及关单。1,601,489 Token，缓存读取 1,499,264，命中率 95.46%。 |

证据组最早一跑使用较深的隔离数据目录，Building-loop 真实报 `ENAMETOOLONG` 并降为文字答复，未建档；标准模式完成。首跑两边文字均满足五项，标准 20,574 Token、缓存命中率 49.75%，Building-loop 聊天回退 5,828 Token、79.75%。它只说明启动失败后两边还能给什么答复，不能拿这组用量比较完整流程。缩短隔离数据目录后，用同一包、同一题重跑两边；上表记录重跑，首跑另存。短路径重跑中 Building-loop 共 25 次工具拒绝，无原生回合错误；工程组有 11 次工具拒绝。工具拒绝包含正确的保护动作和模型填错参数，不能把每次拒绝都算成一处代码缺陷。

工程题中两边都识别新目标并取消 UI、业务报表和全量上线。Building-loop 还明确写清预建报表草稿没有上线授权；这些写在稿里，不能报成账本已复盘。两边都在回滚小节写了“先停新请求、再排空、再回退”，但演练主流程的关开关顺序与该段冲突。Building-loop 还把“至少一次投递”扩大成“重复消费必然发生”，首审实际记录该块为支持；两条冲突流程也曾被首审分别标支持，但同批超过条数上限而未落盘。首审曾在稿件自述及原始证据的参数校验处阻塞，并续回原核验会话；终点未完成，既不能报成最终误放，也不能报成已拦住跨章节冲突。

开工丢尾可定位到[直接指令只保存 256 个字符](../governance/conversation-start.mjs#L257)和[建档只写入摘要及被选摘录](../governance/conversation-project.mjs#L85)。应把完整获准任务作为只读指令传下去，证据摘录保持独立；遇到不能完整传递的输入，显式停下补齐。Windows 深路径错误在[创建锁申请目录](../governance/transactions.mjs#L106)触发。工程步骤则需要对照可执行序列，验证停接、在途排空和回退的全局顺序，不能只逐段验文字。

本轮普通模式的内容更快且得分更高。Building-loop 的实测增量是受控项目文件、会话证据可追查、可恢复的核验记录和未完成时不声称关单。两项都没有同等完工的 Building-loop 结果，因此不能把观察终点用量换算成等质量交付的成本，也不能把本轮推成所有长任务的输赢。原文、评分、阶段和可复算用量见[公开观察数据](observations-standard-comparison.json)。
