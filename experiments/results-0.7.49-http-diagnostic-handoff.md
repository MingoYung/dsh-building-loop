上轮执行方三次漏填复现配方的 `stdin`，进入参数诊断。正确参数在受信公开样例中实测返回 500，但宿主优先给出参数恢复回执。定点测试所用候选包含修正后的回执优先级，安装包 SHA-256 为 `544348fa65ff4e4db2ae39667608c5b34bef7ae1745f3bcd8275c39c7b252f38`，安装清单匹配 59 项。

复验克隆了旧运行的工作区状态、开工记录和四份原生会话日志。原会话标识、原生事件及源码保持原样。为隔离写入，迁移了工作区路径和路径派生的状态文件名。诊断、总控核实和派发由本地脚本调用真实宿主工具。仅在宿主验证确实续派原执行方后，才放行同一官方 DeepSeek Flash 模型。脚本没有写业务源码。

- 冻结起点 `cd8c83344c8543732f1fbd491b8680e213915918da7764d8e367f9dc0a449bd8`，两个请求均为 HTTP 500。受信样例继续复现 `AttributeError`，即 `header_map` 实例无法设置 `_canonical`。
- 诊断员取得行为不符回执并重新分层，总控核实。原生总控事件 334 返回 `reused=true`，原执行会话散列标识为 `da939897660e`。执行方事件 109 读取回执，含两条 HTTP 500、异常及 `hmock.py:545–565` 的定位。
- 执行方事件 121 首次尝试编辑时缺少改动理由，被工具拒绝。事件 127 补全理由后由同一执行方修改 `hmock.py`，在 `header_map.__slots__` 增加 `_canonical`。`templating.py` 和 `requirements.txt` 的哈希保持不变。
- 受控检查与冻结副本再次实际发请求。两次均观察到 `GET /ping` 返回 **200**、`text/plain`、长度 **2**、正文 **OK**，未匹配路由返回 **404**、正文 **not found**。语法、固定依赖与公开用例 **3/3**。最终源码集合 SHA-256 为 `7901bd8fbae1c79f8a57af9441ece615a73d6eb04acde8b174768c9b5bd189ed`。

冻结稿的新增注释有一处事实错误。`ctx_map` 实际直接继承 `GoMap`，自身声明空槽。`header_map` 的槽位修改通过上述运行行为验证，注释原样保留在实测冻稿中。
