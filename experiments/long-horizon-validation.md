# 亿级累计 Token 的长工程验收

## 三种规模需要分别度量

单次上下文峰值反映模型在当前会话能同时看多少材料。累计输入、缓存读取、缓存写入和输出反映整个工程处理了多少模型流量。工作单元、派单交接、目标变更、已关账目和原始证据的数量反映宿主要保存与协调多少项目状态。相同的 1 亿累计 Token 可能来自反复读取一个大上下文，也可能来自很多次短会话。它们会给宿主和交付带来不同负荷。

例如，平均每次请求消耗 10 万输入与输出 Token，1 亿约对应 1,000 次调用，10 亿约对应 10,000 次，50 亿约对应 50,000 次。该换算只用于安排压测批次。真实工程记录实际分布，费用用各类 Token 的实际计价或账单单列。

## 分层实测

| 层次 | 怎样测 | 能证明的结果 |
| --- | --- | --- |
| 宿主状态和容量 | 通过真实函数或原生事件重放权限、账本、签名、审查、日志和恢复。注入并行更新、重复事件、进程中断、目标替换、文件变更和迟到子任务。按账项密度和文件字节加压。 | 机制是否丢账、重复接单、信错旧证据、越权或达到存储上限。 |
| 真实模型长程样本 | 用多次真实目标变更、独立会话和有依赖的交付串成一项工程。用 3–5 个业务领域对照。同一任务的三种模式采用相同业务输入和冻结评估，不为任一模式代写交接。 | 真模型能否在版本和作者更换之后继续沿用正确事实，准确纠错并交付。 |
| 连续生产规模 | 达到更小档位的质量和成本门槛后继续推进同一个实际工程到 1 亿、10 亿和更高。始终保留工作树、历史、队列和事实来源，让老债能够在后来阶段重新出现。 | 在真实长跑里，档位末端是否仍有效。本地事件重放或短样本不能给这档结论。 |

真实长程对照按当前完成度、问题累积量和使用曲线来切样本。每个里程碑同时记录每项需求的实际版本、独立隐藏测试、首份可用稿、最终交付状态、误退次数和返工 Token、原目录接手、过期任务复活、缺源误放和缓存命中。抽查时让新会话只看项目实际文件，询问过去某个决定为什么改变，再用对应的旧版本、目标和证据复验。

测轮换临界点时，以完整阶段和同一工作量为比较单位。对相似任务，保留现有可复用会话、较早或较晚在落盘后轮换作为不同试验组。把累计缓存读取量和单次上下文长度分别记下来，复跑不同业务和不同变更频率。候选阈值应说明在什么范围能节省成本，同时保住交付质量。直到运行结束才知道总量，轮换本身可以按实际累计量与合适的工作边界触发。

## 已测到的容量边界

生产账本状态的提交上限为 8 MiB。对真实写入入口试验，8,388,608 字节可落盘，8,388,609 被拒。单文件及其日志各有 256 KiB 上限。用真实账本导出函数试验，采用有理由与证据的合成历史，250 条且每条 180 个中文字可生成 232,323 字节的待写账本，500 条即超限。条数与理由及证据长度有关。这是当前版的真实工程风险，需先验证分卷、历史可寻址和增量复盘，才能把工作量提升到数百上千个工程轮次。

另外通过插件的真实事件及轮换处理函数注入分别合计 1 亿、10 亿和 50 亿的**合成缓存读取计量**。三组均证实重复事件不重复计量、旧子会话中断后继续复用、到了补查边界才轮换、新执行者从零计量、文件授权未扩大。每组只重放 65 个有效计量事件，过程调用模型次数为零。此结果验证了大数和已覆盖的边界逻辑。调用密度、真实长跑的推理质量、缓存计费和费用仍需按各自的负载实测。

## 更难的工程题

保留上一轮 18/21 项作为冒烟回归。新的发布规划器任务在原项目上继续两次目标变更。G3 加入原子批量回退，涉及跨未应用中间节点追溯、无跨项污染、首个错误优先和每项至少 2,000 个变更。G4 修改批量协议，加入请求 ID 幂等、冲突检测和整批预算，原单项接口继续有效。把固定功能、随机图性质、失败注入、代码结构、用户约束和文档中能验证的断言分别核验。

已用隔离 WSL 校准评分器。正例通过 G3 的 27 项和 G4 的 51 项新增检查，并保住原有 21 项。上一轮全绿的旧程序仍过 21 项，在 G3/G4 新增题分别为 0/27 和 0/51。人为植入部分结果、漏传递依赖、重复计费三种缺陷，评分器全部拦截。这个结果是评分器的自校验。难题的 Windows DSH 原生入口另用独立种子预跑，并确认基础阶段 21/21。付费模型对照需要使用开始前冻结的隐藏样例种子，评估器保留在模型不可见的运行环境。
