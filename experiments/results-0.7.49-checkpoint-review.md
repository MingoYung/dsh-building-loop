# 0.7.49 · 关单和审核节点回放

上级 [实验与验收](README.md) · [0.7.39 正式兼容基线](results-0.7.39-dsh-rc3.md)

候选从正式 0.7.39 的 `a5e5887` 起步，独立封存恢复点继续保存。按原始问题选定故障发生前的入口。历史 Windows DSH 会话有原始工具事件、回执、签名和冻结产物，滚动状态已到末期。因此从相同的约束条件重建原生入口，保留真正的原始事件和确定性重建各自的证据。

本轮隔离运行包核对 59 个文件，SHA-256 `87f208808570486674a9797127f75753118f1a2da6c8ee8f76b1d361b4efca81`。运行包与正式兼容版的差异只涉及 `governance` 中的四个入口和包版本。预检使用同一归档在两类独立 Windows Profile 通过。

维护者登记的公开行为失败与探索性失败分别处理。只接受当前条款、真实受控执行和签名产物都对得上的结果。失败写拒绝回执，交回原执行会话。签名回归继续核旧行为和当前必测，终审和账本照当前结果查。待补查接进宿主持久派发，保留原用户等待和重启去重。

架构文件改动时，目标、授权、实际源码、用例和签名回执仍完全匹配，各审核会话可带回自己已经验证的源码和用例行及原读权凭据。跨章节的自然语言断言可能因别处变化失效，因此每位审核者重新读当期架构，并保留完整独立判断。正文真实性和数字复算模块使用封存基线。

## 定稿前公开 HTTP 工程

0.7.49 原生 `r-5Daoew` 在 C1 有 49 份签名快照，含空底稿，均未达到题面公开要求。服务从不能启动到能回送完整 HTTP 响应，最后连续返回 500。模型两次传输失败并由 DSH 自动重试恢复，随后执行会话继续编辑。多次签名仍返回相同错误，使用隔离宿主的停止信号在 1,182.213 秒冻结 C1。本轮没有有效送审、审核或关单记录，C2 和 C3 未启动。宿主已退出，正式 Profile 受检指纹一致。

独立冻结评分 C1 0/29，固定官方用例全部收集并实际评分，其中 27 项 HTTP 500，2 项无效配置时进程未按评分预期停止。同题旧记录的 C1 为兼容 0.7.39 的 19/29 与 0.7.46 的 0/29。此次将公开请求绑定为受信签名条件，验收路径比旧运行覆盖更多行为，成绩记为一次新运行。程序持续 500 源于请求头类使用空 `__slots__` 却设置 `_canonical`，在处理任何请求时均会触发 `AttributeError`。故障发生在路由前，和旧候选的双斜杠 404 不同。正式 DSH 继续保留已适配的 0.7.39，本候选留作隔离验证。

HTTP 本轮只计原生日志可归属的 149 条响应，共 17,190,665 Token，输入缓存命中 99.14%。其中未命中输入 146,937，缓存读取 16,946,816，输出 96,912。两次传输错误和一次停止前被截的请求没有独立用量。两项长测共计 25,308,676 有记录 Token。定点验证和独立评分复跑的外部模型用量均为 0。

本轮取证的公开测试只传回 HTTP 500，服务日志未进入执行会话。长测结束后将异常类型及限长消息加入 QA 反馈。同一冻结交付 `cd8c8334…` 回放仍明确返回 500，且诊断附上进程实测 `AttributeError` 和 `_canonical`。固定参考实现同一输入得到 200/404，判定通过，正反源文件前后哈希一致。此次重放无需再次调用模型，改动仅在隔离测试器。

## HTTP 首关失败诊断定点

在原冻结源码和依赖 `cd8c8334…` 上开一个隔离 DSH 会话。只跑公开用例 `public-basic-get-and-404`，保留语法与依赖检查，不运行官方 29 项评分或后续关卡。候选安装包 SHA-256 为 `f8bec9eb75adde84c208a442289fab2afa5e7848d13bdf9994b34cb88f883a07`。安装清单匹配 59 项，前置检查和冻结品复验使用同一受信运行器。不计模型的最初预检因 Windows 路径分隔符导致目录检查无法退出，路径正规化后预检通过。

三个不同源码版本在同一目标、角色、只读输入及用例下反复报同一个具体异常时，宿主进入诊断。定点红绿回归验证该行为，完整检查通过、输出变为另一类错误和只读输入变化均有反例。受信诊断不替代交付签名和独立审核。

唯一一次真实 DeepSeek Flash 定点 `r-hYRAdi` 观察到两个请求均返回 500。第 21.123 秒签名记录该失败。受信完整检查及公开示例把 `AttributeError` 传到原执行会话，定位到 `hmock.py` 的 `header_map.__slots__` 与 `self._canonical`。执行方随后三次遗漏配方的 `stdin` 进入参数诊断。诊断员成功重放公开示例并得到真实 HTTP 不符，宿主却优先发出参数恢复回执，源码故障无法按这张回执转交原执行方。更换只读诊断会话后仍无源码变化，230.037 秒手动停止。冻结源码哈希与起点完全一致，冻结结果仍为 500/500，隔离宿主已退出且正式 Profile 受检指纹相同。
