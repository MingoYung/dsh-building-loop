# 0.7.37 · 宿主生成数值及复核凭据

## 改动与口径

受控写入按授权配置生成结果、单位、出处及引用行清单。稿件不再需要执行者手填同一数值，再等预检背对背复算。两道审核仍各自读取当期原文，判断指标范围、单位、依据是否支撑正文。回执保存宿主的计算定义、公式、原始文件摘要和实际数据行，并分别保存各角色的判断。配置、稿件或源数据变化会使旧结果失效。原始文件权限、已读检查、来源版本和独立角色约束继续参与验收。

引用行计数统计当前稿里可由现有定位器识别的物理行，扣除统计行本身。它描述引用写法和数量。引用是否有效、原文能证明的范围，分别由现有出处门槛和审核判断。

## 正反回归

| 场景 | 验证结果 |
|---|---|
| 手写错数、错单位或碰巧填对 | 已登记的宿主结果缺少真实生成凭据时均不能提交 |
| 原文单位为毫秒 | `24 ms → 0.024 s` 通过，`24%`、`24 s`、错误复合单位及质量单位转换被拦 |
| 按总体分母统计 | 原始分子合计除以原始分母合计，正确结果通过；行百分比的简单平均、少引表头、分母为零被拦 |
| 正确稿和角色证据 | 宿主填值和行号，插行后重算，首审和独立复核分别留下实际读过的原始证据与自己的理由 |
| 数字可算但语义范围有缺口 | 审核可据具体原句退回。口径歧义单独挂起，总控确认用户选择后更新总纲，从原执行会话继续 |
| 资料被修改 | 已登记源的版本不匹配阻断生成，关单前重核版本 |
| 普通编号断言漏写同行定位 | 同角色已核实际来源且同一行没有其他已授权出处时，精确退给原执行者；误选来源仍由审核修正参数 |

这些回归用真实工具契约及原始文件验证。运行与失败证据见[结构化记录](observations-0.7.37-host-results.json)。

## Windows DSH 单次样例

同一次校准任务，三个付费阶段均运行官方 DeepSeek Flash，保留原总控、执行者和首审，终审沿用同一独立复核会话。首稿首次受控写入就生成基准 80、对照 62 对应的 **22.5%**，稿件定位到原始 CSV 第 2–3 行。引用统计结果是 1 行，实际为正文第 7 行。两项从首稿到终稿均未人工修改，也没有数字或单位返工。

首审两次重复填写已由宿主提供的证据参数，第三次成功保存两项。随后普通编号断言 C2 有独立证据，正文同行缺少出处，首审反复尝试支持并被拒。原包停止后，经两次未产出模型响应的测试器恢复失败，原首审续接后仍阻塞。该阶段的技术提示排在重新阻塞后才送达，未恢复工作阶段。修正版在原检查点恢复，同一首审实际用明确的缺出处判断退回，原执行者一次局部编辑补齐同行出处和结尾标记，重新送审。冻结原请求的独立回放验证了修正版可由宿主自动退回同一缺项，同时继续拒绝审核者选错来源的参数。

两道审核随后就独立引句的引导词是否属事实产生一次定向重核，依据仍是同一份原文，当时无数值分歧。重核后 14 项实测验收全部通过，原总控按实际内容复盘 2 项账本并关单。三个付费阶段共 43 次工具报错，含主次审参数、总控工具权限及补查提交的当前材料读回。引句前缀分歧的冻结数据也已留档。

Windows 回归 480/480，数值与续接专项 7/7。最终隔离包 SHA-256 为 `1d60e28a48d9ae8692da945d76e2a543835286ca74253b1a58a31dba51fad6b0`，59/59 文件与清单一致。原包和修正版的安装探针及冻结回放均未调用模型。

这次只观察同一个校准样例。以往 R80 的手写引用数字在两次预检遭退；本轮消除了同类作者返工，仍出现审核参数重试和一次非数值补查。样例不同，尚不能估算总体返工率和 Token 差异。当前宿主填充适用于已登记的口径和数据格式。自由文本的取样代表性、是否误用离线数据等，仍靠两次独立判断。正式桌面保持 0.7.35，本轮验收在 G 盘隔离 DSH 中完成。
