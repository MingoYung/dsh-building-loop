# 0.7.0 累计缓存阈值：真实 API 实测与边界

上级：[实验与验收索引](README.md) · [0.7.0 主实测报告](results-0.7.0.md)。

本轮没有足够证据设置通用的“最省钱换会话阈值”。代码题中各档都通过机械检查，但相对热缓存不换组的费用变化均不足 1%；运营数据题存在实质判断错误；授权题的严格得分主要受引用表达影响。两组发生网络失败，缺失用量保留为未知。

本页的内容复核由**审查 Agent**执行，未由真人执行。A 每个完成组只抽查 **10/24 条理由**；B/C 对所有已返回答案逐条复核，并检查失败请求记录。机械检查、审查 Agent 的内容判断和未完成部分分别说明，不把它们合称为全面证明。

## 测什么、怎样交接

这是直接调用官方 DeepSeek HTTP API 的受控消息历史基准，使用实际返回的 `deepseek-flash` 模型标识、`thinking.type=disabled`、`temperature=0`、`max_tokens=384` 和 JSON 输出请求。它不等同于 DSH 派单、工具、审查和账本的完整流程验收；DSH 原生运行结果见[主实测报告](results-0.7.0.md)。

阈值按一个工作会话各请求实际返回的 `prompt_cache_hit_tokens` 累加。达到后先保存当前答案、进度和当前目标，再为下一项建立新消息历史，重新提供相同事实材料及已保存状态；会话累计值清零，项目总计保留。没有预设会话个数，也没有为了达到某个 Token 总量添加无效文字。新会话的输入全部计入费用，没有额外调用模型生成摘要。

这个指标是**累计缓存读取量**，不是单次上下文长度。各组做相同的工作单元后停止；最后一题刚好越过阈值时，不再无意义地新建会话。进度中的 `completedIds` 表示判断尝试已记录，不表示项目交付已经验收。

| 话题 | 冻结资料与工作量 | 中途变化 |
|---|---|---|
| A：代码理解 | 0.6.0 实际治理源码，固定提交 `3b321216b5744d33e37e2cfeeda2b20422c11ea8`；7个文件，141,039字节，24个独立判断 | 第12题后从G1切为G2，每个回答须保留当前版本与范围 |
| B：运营数据 | 明确合成的640条唯一CSV记录及统计规则，28,037字节，24题；预期数字由脚本计算，并另行重读CSV复算 | 第12题后成功率分母从全部请求改为completed；明确要求全量的延迟指标保持全量 |
| C：分层授权 | 明确合成的总纲、模块条款和请求事实，正式组36份独立档案，33,003字节，36题 | 第12题后G2停用export/publish，保留只读与满足条件的restore |

同一话题内的正式组使用相同资料、题序、目标更新点、模型参数与输出契约。标准答案、预期证据位置和脚本计算值只在试验记录中封存，没有送入模型请求。

最初A的1题小样使用了有歧义的 `ruleVersion` 字段，模型填源码规范 `building-loop/1` 而非项目G1。该失败完整保留；经批准明确为 `goalVersion` 后，另开新校准轮，全部正式组统一采用新契约。校准累计缓存为1,013,760，选取250k、500k、750k三个候选。A正式次序为500k→250k→750k→不换，末组用于避免首次冷缓存使不换组处于不公平位置。

C最初24档案共享准备的输入为7,120，预计正常24题不足以触发250k。正式组开始前，经批准增加12个有独立判定意义的授权案例，三个正式组统一扩为36题；新增项涉及明确拒绝与未知的优先级、索引和正文权限的区别、个人资料动作边界、紧急标题不能扩权等。旧24档案准备请求仍单列计费，不混作36题组。B次序为不换→750k→250k；C次序为250k→不换→750k。没有继续扩题或用成功补跑替换失败。

## 质量口径

原严格机械评分要求：标签符合冻结预期；全部引用格式正确、文件真实存在且行号在界内；所需证据组有定位；B汇总题覆盖全部参与计算的记录；当前 `goalVersion` 与 `scope` 正确；完整单个JSON、正确题号、非空理由且 `finish_reason=stop`。这些检查不是自然语言推导的完整证明。

审查 Agent 随后核对理由与冻结源码、规则或CSV原始值。A固定抽查题号为1、2、7、9、10、14、18、21、23、24，涵盖单位、精确引用、推导、权限、目标和无证据统计；每个完成组抽查10/10通过，但其余14条理由未逐条复核。B/C的所有已返回答案均逐条复核。历史原回答和原机械分保持不变，追加独立检查列。

另有两个统一后验辅助口径，均不替代原评分：

- 只把合法的单行定位 `文件:L16` 展开为 `文件:L16-L16`，再执行全部既有文件、行界、证据组、标签、目标及完整输出检查，不补来源、不修答案。
- C25的总纲措辞有宽读／窄读争议：先限定personal数据的export/publish禁令，后写禁令高于恢复例外。冻结预期不改，所有C组统一另报排除C25的敏感性结果，不把争议直接记成模型概念偷换。

## 如何复核公开资料

每个运行表格链接指向独立归档JSON；在其 `artifacts` 中按 `path` 找 `request-*.json`、`response-*.json`、`unit-*.json`、`test-injections.json`、`facts.json`、`summary.json` 和 `independent-validation.json`。请求保留模型参数、消息和SHA，未保存Authorization凭据。历史原记录与原评分保持不变，新增分析列不替换它们。

详细设计、脚本和跨运行复核在[运行脚本与分析归档](data/harnesses.json)中。按 `artifacts[].path` 精确查找下列路径，读取相应 `data` 字段：

| 要核对的内容 | `artifacts[].path` |
|---|---|
| 总设计、阈值及公平比较约束 | `building-loop-threshold-audit/design.md` |

| 冻结题目、标准答案生成与原始数值 | `building-loop-threshold-audit/fixtures.py` |
| 从CSV重新统计的独立结果 | `building-loop-threshold-audit/ground-truth-audit.json` |
| 审查Agent逐条内容复核与A抽查边界 | `building-loop-threshold-audit/manual-review.json` |

自动复算结果：请求SHA、冻结资料SHA、已返回usage分区与总和均通过；同话题正式组资料哈希一致；所有实际交接均在阈值满足且答案已记录后发生，交接状态包含正确的已记录题号与当前目标。追加“所有引用均合法”和`finish_reason=stop`检查后，历史机械得分变化为0条。这些结果证明记录可复算及观察到的交接时序，不证明所有自然语言结论真实。

## 可以采取的改进与仍未证明的部分

可以优先将等价引用写法在宿主确定性规范化，随后维持相同的文件、行界和证据支持要求；要求可计算数字使用已读原始数据复算，并检查计算结果与最终标签是否一致；对多个JSON对象拒绝提交；在交接状态中保留经过验证的输出结构样例。它们是从本轮失败得到的建议，不宣称已在本HTTP试验中修好。

本轮每档只有一次正式观察，缓存冷热、并行外部请求和模型运行差异未被完全控制，未对每档进行独立重复试验或建立统计置信区间。B未通过全部质量要求，C含争议题，两个750k组不完整；不能从这些数据确定通用阈值，或断言复用/新开单独造成了全部质量差异。

大白话：换会话能让历史短一点，但这次没有找到一个到处都省钱的数。先把“算对却判错、能算却说不知道、引用写法不一致”修稳，才值得比较哪一档更便宜。少花Token却交错答案，不算收益。
