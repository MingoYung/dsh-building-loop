从独立封存的 0.7.39 启动隔离重修。此候选只接入 DSH 新旧派单接口兼容、可选的版本化职责文件、正文分块编号误拦修复和架构回执的实际源码补证提示。候选安装包 59 个运行文件，SHA-256 `c2a3a19c15e82b9e835e6b41c4ea01302f11b6018659e398ef53f22e94c38cfb`。当前 Windows DSH 2.0.23-next，内置 DSH 0.2.2-rc.3，在 G 盘隔离 Profile 使用真实 DeepSeek Flash。

总控登记架构后派单。首关启动控制使用真实 Python 进程，即使语法检查通过，也能确实复现 `entry.py:4` 引入不存在接口的错误。执行方通过受控诊断收到首错并修复。新主会话从第一关冻结源码的相同字节接手，目标版本不同。第二关触发诊断后，原执行会话收到定点续派。每关的首审、独立复核和执行是不同的会话。总控、执行、首审与独立复核分别读了对应职责。角色文件采用项目级可选配置，模块细节继续由当前目标、架构和退回项提供。

同身份另有两条宿主集成回归。已中断执行阶段能派回原身份，改目标会使旧审批失效，原审核会话重读目标后核验。绑定过的工程主会话仍要求在换工程目标时重新开工绑定。保留旧回执、旧代码和各自的授权记录。

Node 全仓发现 503 项，提交时全部通过，包括测试辅助模块。独立重放一个公开资料题的冻结旧回执，错误编号拦截 11→0，仍保留 12 项正文补查，把缺证原句加回后仍拒绝。

两关共观测 4,537,753 Token，输入缓存 95.27%。第一关为 1,196,816 和 94.47%，第二关为 3,340,937 和 95.56%。缓存为实际读取量。候选验收窗内正式 Profile 发生变化，正式安装日志证实同期安装的是 0.7.39 兼容包，候选仅安装在 G 盘 Profile。

本轮验证的是重修第一条可运行链路。资料隔离与下游工程交接、难题能力和各角色提示压缩留待后续按单项验证。正式 DSH 使用单独验收的 0.7.39 兼容包。
