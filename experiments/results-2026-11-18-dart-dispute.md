# DART 原稿为何在算对之后仍被退回

**冻结现场里，两位审员都算出 32 分钟。首审另外要求 NASA 说明它怎样得出公告值，于是把一条读者可以复核的算式判成待证。** 新候选的两位审员都保留了原句，但在理由中给两个数加上了摘录没有写出的观测时序。按付费前封存的标准，这两份回执均未通过。原会话保留在原断点，正式桌面继续运行 0.7.39。

## 首次分歧和反复复核分别发生在哪里

真实 Windows DSH 日志中，首次准备时两位各拿到总纲、项目规则、同一份来稿和同一份 NASA 摘录。四份文件的指纹和原稿核验区的指纹分别一致。两位在各自的第 22 个事件就作出了相反判断，此时还没读另一人的意见，也没读改稿。第一次提交都因缺引证被拒，补上引用后的处置依旧相反。来源采集凭据在两人首次分歧后才出现。角色说明和各自会话历史可能不同，原生日志不足以证明模型内部为何作出某个选择。

| 冻结来稿或材料 | 能从中得到什么 |
|---|---|
| 来稿 C2「用 11 小时 55 分减 11 小时 23 分，可以复核初次公布的 32 分钟。」 | 要求判断读者能否复核这个数 |
| NASA 摘录第 3、5 行给出两个时长，第 4 行给出变化 32 分钟 | 数值差为 32 分钟，与摘录报告的值一致 |
| 摘录中关于计算方法和时序的文字 | 这些行没有陈述 NASA 的统计方法，也没有把两个数逐一标成撞击前、撞击后 |

历史首审算对后仍要求原文给出演算过程。历史复核接受了原句，却把两条摘录分别称作撞后、撞前。旧争议流程会将**两位先前的处置、理由和引文**同时交回给每人。于是，某人额外加上的证明要求也成了同事下一轮读到的论据。前者发生在独立判断阶段，后者是可以直接在宿主接口中复现的互相影响。

## 同一 DeepSeek Flash 的定点对照

下表中每一票都来自独立模型请求。同一请求也出现了不同判法。小样本能复现故障，无法把人员角色、模型随机性、材料截取和历史判词各自的贡献换算成百分比。

| 开发对照 | 观察结果 |
|---|---|
| 保持上一轮定点请求字节相同，将两位带理由的旧意见一起给出 | 正确保留原句 1/4 |
| 移除两个旧处置及其辩词，保留原句与证据 | 2/2 正确保留；加入双方签名原文的中立汇总，重复两对为 3/4 |
| 仅匿名、仅交换旧意见的角色名、仅补项目说明、仅补来源登记 | 这四种改法分别为 0/2；打乱旧意见的排列顺序为 1/2 |
| 换成电表。A 表快报 23.0 kWh；B 表单独记着自己的编制规程 | 两位都能算出 A 的 23.0，却都要求 A 也有书面规程才让读者复核。抽走 B 规程后，两位反而放过了无证据的 A 编制方法 |
| 要求逐句另填主体、关系、出处及总处置 | 同题处置正确 4/8，原格式 6/8，弃用该设计 |
| 每次只核一个原句与证据的关系，由宿主登记处置 | 开发样例处置 9/10，配对旧格式为 8/10；有一位仍误退电表原句 |

这批探索使用原定点工具的消息或单变量变体。那份旧请求另含一条编制方法对照句和测试工具附上的计算回执。后面的正式定点验收重新从注册工具生成请求，DART 题只给原争议句。两个阶段的分数不能混作一个通过率。

## 候选改动和放行结果

宿主在原稿争议阶段给每位审员当前原句、总纲条款及授权范围内去重后的证据位置。逐字引句须匹配本角色已读的当前文件指纹。两人分别提交「支持／矛盾／证据不足」、来源和判断依据。宿主据此登记保留、改正或待证，矛盾还要定位原稿中被驳倒的短句。旧投票及理由留在历史记录；升级时，旧的半张双审回执归档，两位都须在新格式下独立重核。

用冻结的 DART 断点与原有角色绑定做定点调用。两份新题分别覆盖港口清册和实验归档，各有四条断言。另将开发中失败的电表原句独立复查。模型只看到真实角色提示、工具输出及与这步有关的工具参数，按注册的争议动作提交。用例驱动器为两边分别执行来源读取、宿主计算和准备动作，每项最多一次填参修正。预计处置和评分程序均未发给模型。这一层验证的是争议节点，不代表模型已自行走完整个 DSH 任务。

| 验收对象 | 处置符合预登记 | 必要原文均已逐字引用 | 两位处置、引用和理由全部通过 |
|---|---:|---:|---:|
| 冻结 DART C2 | 2/2 | 2/2 | 0/1 题 |
| 新题 K，港口清册 | 8/8 | 8/8 | 4/4 题 |
| 新题 J，实验归档 | 6/8 | 8/8 | 3/4 题 |
| 冻结题及新题合计 | 16/18 票 | 18/18 票 | **7/9 题，14/18 票** |
| 另列已知失败的电表 A1 | 2/2 | 2/2 | 1/1 题 |

- **DART 的剩余缺陷。** 两份回执都正确认可读者能算，也都把摘录第 3 行称作撞击前、第 5 行称作撞击后。两行并未写出这两个标签。引文确实存在，不能证明审员对引文加的每一层解释。即使审核双方一致，来源真实性要求也不允许签收。
- **托盘换算的分歧。** 两位都指出每托盘盒数未知，不能仅凭 4 个托盘算出退回盒数，归档单另载退回 13 盒。题目断言「凭托盘数便可算」，两位都选「改正」。封存标签为「待证」，故两票失分。对此题可以讨论「反驳可计算性」与「具体数量缺证」的区别；这里保留原分。另外一份理由称 13 只能直接读取，忽略了原文也可用 104 减 91 交叉检查。
- **首次填参失败。** 港口两条断言各有两位漏填 `disputeScope`。工具定义与其他动作共用字段，这一步的运行时要求必填。4 次首交全被拒绝，之后原样带回真实宿主报错，4 次补交成功。首次失败合计 10,328 Token，已计入总数。
- **Windows 文件身份。** 迁移回归还发现 Windows 下同一签名行的文件名若大小写不同会被列两次。修复采用授权表中的文件名去重。保留旧包后用存档响应回放。新包生成的 24/24 份请求与实测时逐字节一致，4/4 次退回报错、20/20 份落盘回执及阶段流转也相同。旧运行只保留成功调用的外层摘要。

两轮候选都在隔离 Windows DSH 中按清单核对了 62/62 个运行文件，并恢复了四个原角色的同一份日志和断点。最终源码的工作材料与迁移回归 21/21，覆盖、算术、来源变更和修稿等相邻回归 153/153。
