## 发布规划器：同一业务短指令的对照

本组是 **0.7.30 历史配对**。两轮均使用隔离 Windows DSH、DeepSeek Flash（推理关闭）、同一初始项目与同样的业务原文，评分条件固定。普通标准和 Building-loop 都收到「按现有规格做完、保住旧行为和接口」，第二关收到同样的需求修订。标准＋清单组另收事前固定的规划、注释、验证和交接要求，其成绩在[完整报告](results-0.7.30-hard-completion.md#g3g4-发布规划器)中单列。各组第二关接续自己的前一关产物。

| 口径 | 普通标准功能检查 | Building-loop 功能检查 | 普通标准 Token | Building-loop Token | Token 差 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 每阶段前 300 秒，两轮四阶段合计 | 225/240 | **240/240** | 6,611,830 | 7,395,704 | **+11.86%** |
| 按实际终点合计 | 227/240 | **240/240** | 15,754,023 | 25,908,313 | +64.46% |

300 秒是观测点，流程继续到实际结束或停滞。窗口内多通过 15 项，最终多通过 13 项；功能检查通过不等于整个工作流关单。Building-loop 一轮两关都关单并在原目录换会话；另一轮 G3 停在待独立复核，G4 从 G3 的冻结副本接续后关单。产品的签名与审核要求按各模式本来流程执行，标准模式按自身的原生结束状态记录。这里是一个工程的两次重复，不能用来承诺常态 Token 增量、准确率或费用。

300 秒行用[逐阶段机器记录](observations-0.7.30-hard-completion-g-measures.json)复算：按 `mode` 汇总 `stages[].scoreComparison.allPass/allTotal` 和 `stages[].tokenComparison`。最终行使用 `score` 与 `tokenAll`；差值除以普通标准用量。Token 含缓存输入与输出，未返回 usage 的消耗未知。 [完整三组结果及边界](results-0.7.30-hard-completion.md) · [共同输入与评分摘要](observations-0.7.30-hard-completion-inputs.json)

## 当前稳定版：0.7.39 自身复验

同一 DeepSeek Flash 的原生隔离运行验证了 G3/G4 稳定包，另跑一项固定资料校准。没有为 0.7.39 重新跑一组同期标准模式，不能把历史 A/B 的百分比算到本版头上。[冻结实测摘要](observations-0.7.39-stable-capability.json)

| 实测 | 交付 | 已计量 Token |
| --- | --- | ---: |
| 发布规划器 G3 | 功能 **48/48**、冻结后新样例 **16/16**，独立核验与账本关单 | 3,746,238 |
| 发布规划器 G4 | 原目录新会话接手，功能 **72/72**；旧行为 **48/48**、新增 **24/24**；冻结后新样例 **32/32**；独立核验与账本关单 | 9,414,988 |
| 固定资料校准 | **12/12**，数字限定、原文定位、双审与账本，任务自主关单 | 1,102,331 |

这些用例核实了已测试的行为。独立阅读仍发现工程架构里有与源码不符的回退和顺序描述；固定资料校准也不能推断外网事实的总体真实率。[版本说明与 Windows 恢复验收](../docs/release-0.7.39.md)

## 整个项目做了多少验证

**166 条运行记录，554,950,067 个可计量 Token，227 份专项归档材料。** 这个规模以 [公开实验清单](data/index.json) 为统计范围，使用 [verify.py](verify.py) 逐包核对摘要、从原始计量事件重算；含对照、失败、中断和不同版本。验收材料的份数与运行记录的条数分别计数；这一总量未另加本页摘录的专项报告，也不等于供应商实际账单。

历史测过跨文件工程、需求中途变更、伪造来源和错引、数字与单位、权限越界、独立复核、账本及 Windows 强退恢复。[按测试类型看完整归档](README.md)
