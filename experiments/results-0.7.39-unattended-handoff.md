# 0.7.39 · 无人值守补派审核

上级为[实验与验收](README.md)。使用隔离 Windows DSH NEXT、离线候选包以及本地确定性响应。旧版现场原型见 [0.7.36](results-0.7.36-clarification.md) 和 [0.7.38](results-0.7.38-proof-recovery.md)。[机器验收数据](observations-0.7.39-unattended-handoff-native.json)保留前后版本、三次真实强退、调试失败及日志摘要。

| 定点场景 | 观察 |
|---|---|
| 初稿待首审 | 0.7.38 的原总控已空闲却停在 review-ready。0.7.39 由宿主调现有派发入口，独立首审启动，执行方与审核方身份分离。 |
| 修订稿待终审 | 0.7.38 已有 pending-audit 回执却停在 final-audit-ready。0.7.39 自动启动另一名只读复核者。提前交空证明被拒，三块独立证明齐全才进入账本复盘。 |
| 实际等待用户 | 指标澄清维持 blocked，手动 advance 也被拒。另一条测试在 review-ready、总控已空闲时保留实际 DSH 问答请求，未误派。模拟用户从原生入口明确回复后自动继续。 |
| Windows Electron 强退：待派落盘 | 工作区保持原待派检查点，重启并恢复原主会话后自动派出一次。 |
| Windows Electron 强退：已预留审核者，原生未收件 | 恢复使用原审核者 ID、阶段序号与交接编号。原生目录登记与收件各一条。 |
| Windows Electron 强退：原生已收件 | 恢复时仅有原编号的一条派单及一条续做通知，阶段、序号及审核者不变，无重复子会话登记。原审核者实际打开原文并退回范围不符的结论。 |

宿主等待确切主会话和活跃子会话空闲，核对原生收件队列、问答及批准状态、项目澄清、当前目标和材料。签名、架构、来源、阶段绑定和两道审核仍通过原派发及报告入口执行。若原生返回异常，宿主核对持久收件记录，只在未有原派单的情况下重试；已收件强退时，恢复通知沿用原审查身份。

Windows 全套 **496/496**，定点及关联回归 **27/27**。定点用例在 0.7.38 基线通过 1/3，两个待派场景均停住，实际澄清保持等待。包括三个真实 Node 进程强杀点（原生持久接口由测试代用）、两个投递报错点、总控在读取旧游标期间完成新回合和旧签名代码盲审。第一次定点整合为 18/20，两个前投递夹具误让旧宿主提前派发，冻结旧夹具后为 20/20；第一次异步读竞争实测未重查，修复后通过。日志归档于 G 盘本轮目录，候选源码回归见 [定点用例](../test/unattended-handoff.test.mjs)。

三个 0.7.39 隔离安装均核对 59 个运行文件。候选包 SHA-256 为 `65e39183266aa4d5623a80cac03af38c0e421dcc42da46164e6845ffd7b59ee1`。最终候选三次验证共有 40 次本地脚本响应，旧版基线 23 次。外部模型请求及付费 Token 为 **0**。原生冷恢复从 DSH 恢复该主会话时开始，测试直接打开原会话且不发送用户提示。正式 Profile 摘要保持一致。

## 正式桌面同步与冻结

正式 Windows DSH 的 desktop Profile 由 0.7.35 更新至 0.7.39。内置离线安装器使用上述相同包摘要，安装后核对 59 个运行文件和 18 个其他直接依赖。改前的 0.7.35 安装包、Profile 清单、补丁、锁文件和 Building-loop 状态通过摘要核对，纳入固定滚动回退位置。

正式桌面正常退出后通过「DSH NEXT - 修复启动」打开新进程。插件详情显示 v0.7.39，building-loop-project-settings 显示运行中，新会话菜单可看到 building-loop。正式桌面使用与历史会话兼容的内联预设 paidan，引用新版包的治理模块。

重启后，把正式桌面的内联预设及其引用的续轮模块复制到隔离 Windows DSH，复验全部通过。待首审、待终审自动启动不同审核会话。原生问答等待期间不派，明确答复后继续。三次强退覆盖待审落盘、原生送达前和送达后，恢复原会话后同编号只有一条派单。送达后恢复的原审核者实际查阅原文并提交退回。三组共 40 条本地脚本响应，外部模型请求 0。正式桌面以 0.7.39 冻结。
