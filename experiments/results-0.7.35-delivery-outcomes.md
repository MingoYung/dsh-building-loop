# 0.7.35 · 逐项交付与两道审核

上级为[实验与验收](README.md)。

0.7.34 的真实运行读取了有效原始记录和当前总纲，首审及独立复核也给出了有效的来源凭据。但最终候选把 E3 写为仍未决定是否待补，两道审核仍通过，宿主进入 `closed`。本轮冻结旧原稿、两份审核回执、资料和总纲摘要，在正常审核工具中验证有证据且缺结论、当前口径确实未定和有明确结果三条路线。 [原版本实验](results-0.7.34-assertion-proof.md)

| 冻结或派生样例 | 工具实际行为 |
|---|---|
| 冻结原稿引用齐全，只在条件中提及结果 | 拒绝拿条件中的词作为可执行的处置。该项如实标缺结果，回原执行会话补查 |
| 正文有结果，大白话写了不同结果 | 两处有不同的字段值，不能用其中一处取得两处通过 |
| 业务口径确实未定 | 宿主保存已定位的问题和目标版本，等待维护者澄清。原目标直接续跑会被拦，目标更新则转回原审核 |
| 明确处置且正文和大白话一致 | 两道审核分别保存三类证明，各项目的实际原始记录、按规则作处置、总结的一致性。宿主才允许进入账本复盘并关单 |

逐项范围来自当前总纲里的明确编号声明。证据齐备、逐项完成和总结一致是分别核对的三件事。简明处置字段有唯一的位置，作为解释的附文仍照原机制独立复核。宿主能核对字段和证明的结构与来源，字段所表达的处置是否合法仍需两位审核者依据实际材料判断。冻结的正反回归 **7/7**，其中包括跨章节借用、过期或替换审核证明、重复声明和只有条件词的字段。真实模型按原项目业务提示走单一路径。

精确候选包收录并核对 58 个宿主文件。旧结果和候选工具回放、真实宿主进度、审批与撤回的依据见[机器记录](observations-0.7.35-delivery-outcomes.json)。修改前的源文件和对应变更记录保存在同一滚动位置，正式桌面的回退包由原 Profile 单独管理。
