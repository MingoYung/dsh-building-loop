# ClearAI 后续验收准备（尚未放行）

用户目标依次为：短提示下完整交付优于标准加清单；随后与 ClearAI 比较同任务实际完成度及资料真实性；最后再优化用量。完整隔离验收通过及正式 DSH 同步是本试验的前置条件。计划、历史无模型安装预跑与实际模型结果分开记录。

- 工程采用同一短业务提示、相同底稿和两段目标变更。标准、Building-loop、ClearAI 分开使用隔离 Profile。若三方不能用相同模型、联网能力、可用资料及权限，则将不能控制的变量单列；不解释为模式本身的差距。
- 以交付实物冻结后分阶段评分：业务要求完成、旧功能保留、隐藏样例、职责与注释、原目录接续。没有提交产物、等待用户、中断或流程未完成分别登记。
- 资料套题事前独立登记：可取得且支持结论的原始材料；看似真实但不存在或没有取得的来源；真实来源却不支持结论；摘录范围与整页不同；合理推测与事实区分；已提供但相互矛盾的来源。按原件与当前版本评分，必要时用公开原始页验证；短摘录只证明它的覆盖范围。
- 独立记录错误来源或推断的放行率、正确材料的保留率、每个交付结论的可追溯率、有效结论交付率。只有三者共同看才能识别“一律拒绝”和“一律通过”。任务完成度主列，资料真实性单列，Token 与缓存末列。不要用同模型共识作真值。
