# 0.7.12 会话内项目协作

验证目标是在 DSH 输入框完成授权，并观察宿主实际启用的工具。Windows 使用已安装 DSH NEXT 自带的 Electron 宿主与 Web CLI。隔离 Profile 测试的安装包 SHA-256 为 `e3a4415f5495947dca015d788a4420b78d5641eab1d22b399a62ee6b46aebbca`。模型请求使用回环测试替身，检查实际发出的工具契约。

## 对照和修复

| 路径 | 观察与处理 |
|---|---|
| 0.7.11 基线 | 标准模式和 Building-loop 均无会话协作入口。未配置的外部工作区可普通聊天，DSH 内部默认工作区仍因与宿主数据目录重叠而报错。 |
| 0.7.12 首轮图形测试 | 预设切换、面板与键盘焦点通过。文件浏览请求因缺少客户端服务声明被宿主拦截，随后补齐客户端注入。 |
| 0.7.12 首轮原生请求 | 客户端额外传入 `cwd` 时，首轮编解码忽略该字段，文件仍只写入宿主记录的实际工作区。最终请求结构明确拒绝未声明字段。 |

## 最终回归

| 测试 | 结果 |
|---|---|
| Node.js | 268 项通过。覆盖首配文件保留、路径与链接限制、会话隔离、子会话继承、关闭后无项目账本及开关记录损坏后的恢复。 |
| 实际 Windows DSH 图形界面 | 11 项通过。标准模式隐藏入口，Building-loop 草稿和已开始的会话均可设置。在深色模式和 820 像素视口检查弹层与键盘焦点。能在默认工作区直接聊天，从嵌套目录选择文件，拒绝越界路径，生成准确授权并启用。 |
| 同工作区的两条会话 | 开启的会话请求包含 `building_loop`、`building_loop_file`、`building_loop_ledger`。另一条会话默认无工具，可独立开启再关闭，授权文件未被重写。重新加载并打开两条会话后，各自状态与宿主工具清单一致。 |
| Windows Electron 宿主 | 新旧预设同时安装、仅保留旧 `paidan` 两个场景各 20 项通过。拒绝匿名、非所有者、标准模式、子会话、正在运行的主会话、错会话和伪造目录参数。 |
| Windows 宿主重启 | 前后共 27 项通过。新旧预设保存的关闭状态均恢复，其他会话独立，已关闭的会话可由所有者重新开启。两个宿主进程均正常退出。 |
