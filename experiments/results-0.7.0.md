# 0.7.0：调用成本、共同误判与滚动交接

上级是[实验索引](README.md)和[项目总纲](../README.md)。机制与配置见[成本和交接规则](../governance/efficiency.md)，完整跨话题结果见[阈值报告](results-threshold-0.7.0.md)。所有真实运行、失败、请求和原始用量从[数据清单](data/index.json)进入；运行器、封存设计、复核结果与改动记录在[脚本和辅助材料快照](data/harnesses.json)。本页中的内容复核由审查 Agent 完成，不冒称是真人人工审查。

## 本轮问题与实现

目标是减少参数错误、重复核验和交付后的无效调用，同时保留全文覆盖、原始证据、推导核验、独立反证、当前目标和任务账本标准。“总任务有多少 Token”不需要预知；交接策略只观察当前执行会话已实际产生的缓存读取量，在工作已经落盘的安全边界决定是否换会话。

- 角色工具限制前移到真实 DSH 工具解析时，避免首次模型请求已经冻结了原生工具后才隐藏。执行 guard 继续独立拦截，普通预设不受影响。
- `prepare` 给当前角色真实可见、带行号的读包和参数契约；只有实际返回的行与覆盖块算已呈现，不能凭 pending 编号猜下一块。摘要和分页有界。
- 覆盖状态默认简短；有效块增量保存，错误块清除旧证明并指出具体问题。逐字片段错配给出当前块、片段序号和具体边界位置，不替模型编造证据或更改正文。
- 两轮核验的事实分类有分歧时，必须逐项处理争议，不能原样再送。同角色、同版本的已读记录与未争议证明可复用；每角色仅留当前一份，目标、候选或来源改变就失效。两角色不共享对方完整证明，最终验收仍全量重核引用与版本。
- 子会话成功交付且通知总控后结束本轮；通知失败不冒充完成。反证提交只需 `audit`，不重复发送宿主已保存的整份 checks、quality 或正文。
- 大白话默认必须是正文最后实质段；常见 Markdown、表格、HTML、脚注和错例追加都检查。非正文产物由维护者明确关闭此项，执行者不能自行绕过。
- 缓存轮换是可选正整数参数，默认不设。实际执行会话用量按 turn/step 去重，只有交付后的下一次补查才会轮换；被阻塞的未完成阶段保持原会话恢复。总控和核验者不会因执行方阈值被替换。
- 核验和反证只接收宿主中性派单，不转发总控的自由 note 或前审结论。派单阶段本身仍可推知，所以不称严格实验双盲。
- `unlisted` 必须与当前覆盖记录里被拒的事实、具体 `finding.quote` 对齐；纯标题或正确半句不能变成作者的补查债。明确编号错例与常见 Markdown 前缀归一化，不要求为换标签改写正确内容。
- 可选 `ledgerDocument` 是明确授权的宿主完整快照，列出全部当前条目、完整 ID、状态、依据与版本，不再让模型转写出遗漏或虚构历史。

两组都正确退回三个种子错误、保留七个正确对照，宿主机械闭环与实际用量/角色权限验证通过，七项账本的取消、覆盖和保留与新目标一致。新开组最终正文 14 行、两审各 21 块；复用组 29 行、各 45 块。长度和返工路径不同，费用差不能作为复用策略的因果收益。

复用组的“群体层面”没有明确写求平均或聚合单位，合理地读作对这一组模拟观测的描述时可以成立；读作统计层级则缺少来源说明。正式复核保留 `needs-scope-clarification`，确定虚假正文事实计数为 0，不能把歧义当作已经证实的虚假事实。两审额外声称各引用处均写了“模拟”或“本例”，其中两处实际没有；统一来源声明不支持这个逐处标注断言，核验证明可靠性问题独立保留。敏感性复核前的较强派生裁决另存并标明已取代，原始实验文件未改。

复用组第二轮补查包含一次可避免的格式误退：已经标明“错例（字段混滑）：……——错在……”仍被要求改成严格的“错例：”。最终代码以统一、有限括号标签语法修复，实际原句和正反例本地回放通过；仍要求真实反证。新开组的过程自评计数、首次过度判为矛盾和最终简表的旧名称单独记录，没有当成最终正文错误，也没有从过程成本中删除。

99 项最终版本另补了失效分类原因清理、软换行/缩进续行绕过、伪代码围栏关闭和末尾说明识别。相对真实 pair，仅 `governance/index.mjs` 与 `governance/preflight.mjs` 两个运行模块改变。安装资格单明确使用“实测基础＋局部改动本地验证”，`realModelRetested=false`；不是将新版本标为真实模型全部通过。

比较沿用 0.6.0 v2 的同一组短摘录、三个错误和七个正确对照，故意在首次审查后把项目从交互看板改为中文说明。比较对象为完整执行链：总控、执行、首审、补查、终审、独立反证和账本，不只计算补查子会话。

最后一批在首次失败后显式启用 `ledgerDocument`，任务规则和总控简报改为由宿主导出账本，避免继续测已知会虚构历史的模型转写。种子候选、三个来源正文和目标前后版本均未改变；这项输入和实现变更已写入每个 run.json，跨批差异不能被描述为只有“复用/新开”一个变量。来源是可定位的官方短摘录和明确标注的合成逻辑记录，不能把短摘录当成整页取证或实际生产数据。

固定材料自身还有一项元数据瑕疵：NIST 摘录第 4 行沿用了 GitHub 的列表摘录说明，属于不相关的取得说明，不是 NIST 原文；相关性结论只引用第 6 行的实际原句。为保持组间输入一致，本轮没有悄悄改写材料；原件与这一限制一并公开。

旧 0.6.0 两组相差 941,921 Token，其中总控差 784,768（约 83.3%），仅账本复盘差 573,288（约 60.9%）。因此不能把旧总量差全部归因于“复用更贵”。旧两组交付后的 idle 响应仍分别消费 235,147、313,888 Token。具体分阶段统计、错误类别与读取重复率见脚本快照里的 `building-loop-efficiency-audit/baseline-analysis.json`。

## 共同误判：把变量拆开

旧 131714Z 的第一核验与反证都是首次新建会话；两者已经看见相反证据，却擅自把没有标识的错误断言解释为作者有意展示的教学反例。这一失败不以补查执行会话复用为前提。旧记录没有完整有效提示摘要，无法再唯一划分“同模型”和“共同提示契约”的因果贡献。

本轮额外做官方 API 受控诊断，固定 12 条材料和答案，只改变以下因素。每个组合重复两次，合计 24 组、288 个判断。

| 因素 | 实际水平 | 能说明的范围 |
|---|---|---|
| 模型 | `deepseek-flash`、`deepseek-v4-pro` | 同厂商两个可用模型，不等于独立训练来源或异厂商验证 |
| 核验方法 | 支持优先、反例优先 | 同证据门槛，改变检查次序；不把多数票当真相 |
| 会话历史 | 新会话、中性历史、历史错判锚定 | 错判历史是从旧事件取出的受控输入，不冒称重现原 DSH 会话 |

全部 24 组格式正确；120 个错误判断均退回、168 个正确判断均保留。包含四次中性历史准备，真实共 28 次请求，51,051 Token（缓存 14,592、未缓存输入 24,592、输出 11,867），估费 $0.026176804。原始请求、响应、参数、时间、SHA、准备费和分组用量见[诊断原件](data/building-loop-causal-audit/20261107T143055Z.json)。

**这是评测上限现象，不能据此给三个因素排唯一主因，也不能宣称共同误判已经消除。** 受控短题全部判对，真实 DSH 长流程却仍暴露了相邻块错配、分类争议循环和首次工具展示时序问题。今后要基于这些实际失败扩充封存材料，保留有效提示与工具集合摘要，分别测变量。完整代码、请求和复核范围在归档中，未执行的 GPT 配置不算跨厂商实测。

发现 151713Z、151723Z 的新语义误放后，另封存两份实际完整错误稿及只修问题子句的正确对照，做 8 次固定调用：Flash／Pro × 中性派单／实际前审结论泄漏 × 两次重复。每次都是新会话，四稿同请求，不改变核验方法。这是发现问题后的定向诊断，不能伪装成预注册泛化基准。

结果为 **0/8 次同时满足契约和正确区分四稿**：4 次输出完整有效，却各放过两份错误稿、保留两份正确稿；另有 Pro 截断两次、Flash 非逐字引句两次。次级口径只看实际完整返回的 30/32 个稿件对象，14 个错误稿均误放、16 个正确稿保留，截断部分不补成成功。共 74,758 Token（缓存 4,864、未缓存 36,344、输出 33,550），估费 $0.064201532，失败成本全计入。[完整诊断报告](results-diagnostic-0.7.0.md)与[该轮原件](data/building-loop-causal-audit/20261107T154044Z.json)保留逐行理由和复算。

实际理由显示两种共性：只核了正确因果主干，没证明附加的统计层次；拿外部来源自己的“合成”标题去证明本稿所有引用都已标注。原生产的错误后缀已经单独成块，两审仍判支持，所以不能声称切短句就能修好。新会话和中性供料也出现同错，说明复用、前审泄漏都不是这两处失败的必要条件；同厂商模型、共同方法与注意力分配的唯一贡献仍未知。最后一批补充了对象对齐和独立附加断言的强制提醒，并未把提醒冒充确定性语义证明。

## 未知总任务的滚动阈值

阈值试验直接控制官方 API 的消息历史，和 DSH 工具闭环分别记录。达到单个会话的累计缓存阈值后，先持久化结果、当前目标和已完成事项，再给下一单元新建历史，项目累计不归零；工作完成就停止，不凑 Token，也不预设换几次。

三个话题是：冻结到 0.6.0 提交的真实代码、640 条明确标注的合成运营记录、分层授权和例外档案。A 校准后比较 25 万、50 万、75 万和不主动交接；再把候选 25 万、75 万与不交接放到 B/C。C 正式组开始前扩为 36 个不同判断，以观察安全交接，批准、理由和新增案例全部留档。

| 关键观察 | 实测事实 | 可以作出的判断 |
|---|---|---|
| A 代码题 | 四档各 24/24 标签、引用和目标字段合格；每组理由抽查 10/24 | 25 万比热缓存不换只便宜约 0.46%，不足设默认 |
| B 数据题 | 不换内容复核后 14/24；25 万原严格 8/24，等价单行引用规范化后 12/24 | 存在算对数却判反、双 JSON、能算却说不足等问题，质量优先；部分差异发生在交接前 |
| C 授权题 | 规范化合法单行定位并排除有措辞争议的 C25 后，两个完整组各 35/35 | 这是后验辅助口径，原严格评分保留；首轮冷热分开后费用排名翻转 |
| 两次网络失败 | B75 万首请求、C75 万第 15 请求 TLS EOF，无 usage | 缺失费用未知，不按零计，也不当完整对照 |

全阈值实验含失败小样、校准与准备费：259 次请求、257 份原始响应、2 次用量未知；已知 7,179,903 Token，其中缓存 7,000,320、未缓存 162,785、输出 16,798，已知估费 $0.05549751，另有未知部分。逐组累计、输入峰值、实际交接、费用和语义复核边界均见[完整阈值报告](results-threshold-0.7.0.md)。

累计缓存读取不是当前上下文长度。A 不换组累计缓存约 106 万，单次输入峰值约 4.5 万；两个数字不能混为一谈。该轮没有确定跨话题、跨模型的最佳区间，25—75 万只是实际测试过的候选，不能写成推荐区间。生产配置默认不设置阈值。

## 冻结、安装与归档
