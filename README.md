# dsh-building-loop

**一句话交代目标，后续按项目推进。** Building-loop 是 DeepSeek Harness（DSH）的长任务模式。你告诉它要交付什么、哪些业务边界不能动。Building-loop 按当前会话判断该直接回答、澄清还是开工；确认后自动建档、分工、核验和记账。需求变了更新目标，新会话接手时可以顺着项目文件找到现状和证据。

**当前稳定版：0.7.39** · [下载验收包（GitHub Release）](https://github.com/MingoYung/dsh-building-loop/releases/tag/v0.7.39) · [这次更新了什么](docs/release-0.7.39.md) · [安装](#安装) · [实测与复算](experiments/README.md)

## 同一条短指令，多通过 15 项工程检查

> **开工示例**：把发布规划器的批量回退按 `SPEC.md` 做完，之前正常的行为和接口保住。做完告诉我结果。

在发布规划器 G3/G4 的历史对照（Building-loop 0.7.30）里，普通标准模式和 Building-loop 用同一个 DeepSeek Flash、同一份底稿和同样简短的业务指令。用户没有额外逐项交代怎么拆任务、做回归、留回执和接手。两轮、四个阶段各看前 300 秒：

| 同一短指令 · 每阶段前 300 秒 | 普通标准模式 | Building-loop |
| --- | ---: | ---: |
| 固定功能检查 | 225/240（93.75%） | **240/240（100%）** |
| 已计量 Token | 6,611,830 | 7,395,704（**+11.86%**） |

**多通过 15 项，提升 6.25 个百分点。** 这组用量对应 300 秒观察窗口。任务在窗口后仍可继续，完整交付的用量与结束状态见[同题复算](experiments/showcase-0.7.39.md)。Token 包含缓存读取，和账单金额是两回事。

**验证规模：166 条公开测试运行记录，累计 5.55 亿可计量 Token。** 来自可复算的历史公开归档，覆盖真实模型、对照组和专项试验，包含失败和中断；这是验证投入，不是单次任务用量。[数据与复算入口](experiments/README.md#验证规模)

**当前稳定版实测：** 0.7.39 在隔离 Windows DSH 用 DeepSeek Flash 完成 G3 **48/48**、G4 **72/72**，在原目录换新会话接上第二关，两关都走完双审、账本复盘并关单。同包另做过 **496/496** 项 Windows 回归及 **3 个**强退恢复场景。[0.7.39 版本与验收](docs/release-0.7.39.md)

## 你少交代的是流程

- **目标变了，按新版继续。** 总纲、分块索引和交付正文保存已确认的方向。旧计划进账本复盘，按当前目标决定要继续、延期还是取消。
- **有结论，就能回到原文。** 核验者分别检查证据、范围与结论。已配置的数字由宿主复算，缺证、错引和版本失效可追到具体位置。
- **查进度，看回执和成果。** 总控分工，执行方在授权范围内修改，能复用的工作由原会话续做。首审、独立复核和账本完成才会关单；到待审核阶段没人接时，0.7.39 会自动补派。

适合已有业务资料、需要交付可回查成果的工程与研究。简单问题可以直接聊；需要你决定的业务口径、权限和资料范围仍会先确认。

## 解决哪些问题

<details>
<summary>展开：权限、恢复、证据与账本</summary>

| 长任务中的痛点 | building-loop 的处理方式 |
|---|---|
| 会话压缩后忘了原目标，沿旧摘要越走越偏 | 三级文件保存当前目标、分块和正文，接手沿总纲按需读取。阶段权限和任务状态由宿主持久保存。 |
| 执行方在同一版源码上反复遇到同类错误、反复试探 | 宿主暂停执行，总控分层，只读子会话用现行版本做最小复现。总控核实后交回原执行会话定点修复。 |
| 主会话混入大量实现细节、临时话题，思考和回复偏离全貌 | 总控和执行方分开。总控按文件白名单管理中央文件与回执，模块正文由授权子会话处理。 |
| 同一分块反复新开子会话，重复读材料、交接和返工 | 同一工作单元默认续用原执行会话，核验方保留独立身份。真实对照记录补查与全程用量，项目可据此判断复用效果。 |
| 参数填错、查状态反复返回全文、交付后还继续消耗 | 按角色显示可用工具，分页准备真实材料，只重交无效核验块；交付并通知成功后结束子会话当前轮。可按已测条件在安全边界滚动交接，默认不预设万能 Token 阈值。 |
| 回答有出处却对不上原文，数字或单位算错 | 宿主核实际已读行、原文版本和已登记来源凭据。已配置计算由脚本复算，独立核验判断证据能支持的结论与边界。 |
| 补查改掉应逐字保留的引句，或把必需的统计整条删掉 | 维护者可在当前目标登记原句、必需标记及组合统计来源。宿主在送审前核正文是否保留并按当前稿复算，验收和关账继续复查。 |
| 编号事实没问题，说明段却混入偷换概念或无据因果 | 宿主从正文生成全文清单，每块必须有分类和核验记录。推导逐项列前提、桥接依据、范围与反例，再由另一个只读子会话独立复核；未覆盖或被判断为未证实的事实不能关单。语义判断本身仍可能共同出错，真实失败在实验中保留。 |
| 临时需求插入后忘了旧计划，中断任务长期丢失 | 用户消息、派发单元和中断自动进入账本。总控也可登记后续计划。每轮验收后强制读账本，结合最新现状逐项保留、续做、延期或有依据地完成、覆盖、失效。 |
| 任务规划过时仍被机械执行，别人已做完的工作重复做 | 验收绑定当前目标版本；目标变更后重新核受影响的交付。覆盖指向已验收的替代单元，失效须引用现状，已有请求沿用原账目，迟到消息重新复盘。 |
| AI 自称完成，交付后才发现缺证据或缺步骤 | 交付读回、独立事实与质量核验、账本复盘构成连续门槛。通过回执落盘并完成本轮复盘后，单元才关单。 |

长期推进由这些阶段和可恢复记录串联。外部材料的真实来源、研究口径和方案优劣仍由领域证据与独立核验判断。当前机制与实测范围见对应分块。

配置 `ledgerDocument` 后，宿主导出当前账项、状态和已登记依据。账本过长时生成索引和分卷，旧账可按编号回查，复盘可按当前待处理事项分页。生成账本时遇到进程退出，宿主按权威提交点核对或恢复本次写入的文件、日志及滚动备份。模型登记的理由仍需结合当前材料复核。

## 安装

兼容基线为 DeepSeek Harness `0.2.2-rc.1`，对应 DSH NEXT `2.0.22-next`。Desktop 和 Web 的插件安装入口各自管理对应的 Profile。

- Windows Desktop 可从侧栏「插件」打开「添加插件」，选择从 [0.7.39 Release](https://github.com/MingoYung/dsh-building-loop/releases/tag/v0.7.39) 下载的 `.tgz` 安装包，或选择仓库来源。
- 命令行管理 Desktop 时，先启动应用初始化目标 Profile，再使用 DSH NEXT 打开的内置终端和它自带的 `dsh`。安装后重新打开应用并核对模式。Windows 系统终端里的 npm 版 `dsh` 只用于它自己管理的 Profile。

```powershell
dsh plugin --profile desktop add github:MingoYung/dsh-building-loop
```

Web 用户在 Web 使用的终端安装。

```powershell
dsh plugin --profile web add github:MingoYung/dsh-building-loop
```

安装 `dsh-building-loop` 后，在新会话的模式列表中选 **building-loop**。验证指定版本时可用实际 `.tgz` 路径替代仓库地址。从旧包 `building-loop` 迁移时，先从同一 Profile 移除旧包，再安装新包。两者使用同一个预设 ID。

选中 **building-loop** 后直接发消息。AI 根据本会话的目标、交付与工作范围判断是直接回答、继续澄清，还是提议开工。提议出现在输入框上方，可选 **开始建设** 或 **先讨论**。明确发出「开始调研……」或确认上一份提议也可启动。确认后宿主自动建立总纲、索引、交付稿和账本，原会话继续推进。 [会话开工与文件授权](governance/README.md)
