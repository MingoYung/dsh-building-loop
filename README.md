# building-loop

DeepSeek Harness 的长任务 Agent 预设，适用于项目建设、深度研究和需要多轮接力的工作。把项目现状、任务和证据放在可追溯文件里，总控维护方向与进度，执行方和核验方在各自权限内完成调查、修改与验收。

## 解决哪些问题

| 长任务中的痛点 | building-loop 的处理方式 |
|---|---|
| 会话压缩后忘了原目标，沿旧摘要越走越偏 | 三级文件保存当前目标、分块和正文，接手沿总纲按需读取。阶段权限和任务状态由宿主持久保存。 |
| 主会话混入大量实现细节、临时话题，思考和回复偏离全貌 | 总控和执行方分开。总控按文件白名单管理中央文件与回执，模块正文由授权子会话处理。 |
| 同一分块反复新开子会话，重复读材料、交接和返工 | 同一工作单元默认续用原执行会话，核验方保留独立身份。真实对照记录补查与全程用量，项目可据此判断复用效果。 |
| 回答有出处却对不上原文，数字或单位算错 | 宿主核实际已读行、原文版本和已登记来源凭据。已配置计算由脚本复算，独立核验判断证据能支持的结论与边界。 |
| 临时需求插入后忘了旧计划，中断任务长期丢失 | 用户消息、派发单元和中断自动进入账本。总控也可登记后续计划。每轮验收后强制读账本，结合最新现状逐项保留、续做、延期或有依据地完成、覆盖、失效。 |
| 任务规划过时仍被机械执行，别人已做完的工作重复做 | 账本处置要写理由，完成、被覆盖和失效要引用本轮读过的现状文件或验收回执。保留记录，下一步由当前目标决定。 |
| AI 自称完成，交付后才发现缺证据或缺步骤 | 交付读回、独立事实与质量核验、账本复盘构成连续门槛。通过回执落盘并完成本轮复盘后，单元才关单。 |

长期推进由这些阶段和可恢复记录串联。外部材料的真实来源、研究口径和方案优劣仍由领域证据与独立核验判断。当前机制与实测范围见对应分块。

## 安装

兼容基线为 DeepSeek Harness `0.2.2-rc.1`，对应 DSH NEXT `2.0.22-next`。在 DSH 终端安装。

```powershell
dsh plugin --profile desktop add github:MingoYung/dsh-building-loop
```

安装 `dsh-building-loop` 后，在新会话的模式列表中选 **building-loop**。本地开发可将安装地址换成本仓库路径。从旧包 `building-loop` 迁移时，先从同一 Profile 移除旧包，再安装新包。两者使用同一个预设 ID。

项目维护者先从[派单分块索引](docs/work-delivery.md)查看授权示例，在工作区根创建 `BUILDING-LOOP.json`，再开会话。清单缺失时受控文件工具会拒绝访问。
