# dsh-building-loop

DeepSeek Harness 的长任务 Agent 预设，适用于项目建设、深度研究和需要多轮接力的工作。把项目现状、任务和证据放在可追溯文件里，总控维护方向与进度，执行方和核验方在各自权限内完成调查、修改与验收。

## 解决哪些问题

| 长任务中的痛点 | building-loop 的处理方式 |
|---|---|
| 会话压缩后忘了原目标，沿旧摘要越走越偏 | 三级文件保存当前目标、分块和正文，接手沿总纲按需读取。阶段权限和任务状态由宿主持久保存。 |
| 主会话混入大量实现细节、临时话题，思考和回复偏离全貌 | 总控和执行方分开。总控按文件白名单管理中央文件与回执，模块正文由授权子会话处理。 |
| 同一分块反复新开子会话，重复读材料、交接和返工 | 同一工作单元默认续用原执行会话，核验方保留独立身份。真实对照记录补查与全程用量，项目可据此判断复用效果。 |
| 参数填错、查状态反复返回全文、交付后还继续消耗 | 按角色显示可用工具，分页准备真实材料，只重交无效核验块；交付并通知成功后结束子会话当前轮。可按已测条件在安全边界滚动交接，默认不预设万能 Token 阈值。 |
| 回答有出处却对不上原文，数字或单位算错 | 宿主核实际已读行、原文版本和已登记来源凭据。已配置计算由脚本复算，独立核验判断证据能支持的结论与边界。 |
| 补查改掉应逐字保留的引句，或把必需的统计整条删掉 | 维护者可在当前目标登记原句、必需标记及组合统计来源。宿主在送审前核正文是否保留并按当前稿复算，验收和关账继续复查。 |
| 编号事实没问题，说明段却混入偷换概念或无据因果 | 宿主从正文生成全文清单，每块必须有分类和核验记录。推导逐项列前提、桥接依据、范围与反例，再由另一个只读子会话独立复核；未覆盖或被判断为未证实的事实不能关单。语义判断本身仍可能共同出错，真实失败在实验中保留。 |
| 临时需求插入后忘了旧计划，中断任务长期丢失 | 用户消息、派发单元和中断自动进入账本。总控也可登记后续计划。每轮验收后强制读账本，结合最新现状逐项保留、续做、延期或有依据地完成、覆盖、失效。 |
| 任务规划过时仍被机械执行，别人已做完的工作重复做 | 验收绑定当前目标版本；目标变更后重新核受影响的交付。覆盖指向已验收的替代单元，失效须引用现状，已有请求沿用原账目，迟到消息重新复盘。 |
| AI 自称完成，交付后才发现缺证据或缺步骤 | 交付读回、独立事实与质量核验、账本复盘构成连续门槛。通过回执落盘并完成本轮复盘后，单元才关单。 |

长期推进由这些阶段和可恢复记录串联。外部材料的真实来源、研究口径和方案优劣仍由领域证据与独立核验判断。当前机制与实测范围见对应分块。

配置 `ledgerDocument` 后，面向用户的账本由宿主完整导出当前账项、状态和已登记依据，模型不能二次转写遗漏。生成账本时遇到进程退出，宿主会按权威提交点核对或恢复自己写入的正文、日志及滚动备份。模型登记的理由仍需内容复核。结构齐全、两位核验一致或缓存命中高，都不能单独证明结论真实或费用最优。

0.7.9 增加 Windows 并发和自动记账恢复、完整单位核验、共用 Markdown 结构、明确出处绑定和按当前材料收敛复核。Windows 原生宿主的新装、激活、升级和回退，以及最终 DeepSeek 复用和新开对照均有验收记录。[四项放行与真实对照](experiments/results-0.7.9.md)

## 安装

兼容基线为 DeepSeek Harness `0.2.2-rc.1`，对应 DSH NEXT `2.0.22-next`。Desktop 和 Web 的插件安装入口各自管理对应的 Profile。

- Windows Desktop 可从侧栏「插件」打开「添加插件」，选择该版本的发行包或仓库来源。
- 命令行管理 Desktop 时，先启动应用初始化目标 Profile，再使用 DSH NEXT 打开的内置终端和它自带的 `dsh`。安装后重新打开应用并核对模式。Windows 系统终端里的 npm 版 `dsh` 只用于它自己管理的 Profile。

```powershell
dsh plugin --profile desktop add github:MingoYung/dsh-building-loop
```

Web 用户在 Web 使用的终端安装。

```powershell
dsh plugin --profile web add github:MingoYung/dsh-building-loop
```

安装 `dsh-building-loop` 后，在新会话的模式列表中选 **building-loop**。验证指定版本时可用实际 `.tgz` 路径替代仓库地址。从旧包 `building-loop` 迁移时，先从同一 Profile 移除旧包，再安装新包。两者使用同一个预设 ID。

在未配置的工作区，可以用 Building-loop 普通聊天。要读取项目文件或派单，请让项目维护者在当前工作区根创建 `BUILDING-LOOP.json`，再在同一会话继续。 [授权示例](docs/work-delivery.md)
