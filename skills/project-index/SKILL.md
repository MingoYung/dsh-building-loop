# 项目索引契约 v1

从项目的 `AGENTS.md`、`DISPATCH.md` 或任务单定位一级总纲、维护人和记录路径。项目现状以受管的现行文件为准。摘要、会话历史、哈希和旧备份可帮助定位，判断时回到文件和证据。

## 一、三级文件

项目或深度问题先规划三级。沿用项目现有入口和命名。新项目先定总纲、分块、各块维护者和正文落点，获授权后建档。缺少会影响落点或范围的决定时，先问清对应部分。

| 级 | 名字 | 放什么 | 谁先读 |
|---|---|---|---|
| 1 | 整体总纲 | 目标、边界、分块入口、全局进度和阻塞 | 每个接手者 |
| 2 | 分块索引 | 本块范围、负责人、正文路径、进度和依赖 | 负责该块的人 |
| 3 | 实质内容 | 规格、实现、研究、来源、回执和证据 | 按任务读取 |

规划和读回都走 **1 → 2 → 3**。上层保留导航和自己负责的状态，下层保留正文。在对应章节就地插入、修订或撤销。新增、移动或删除文件时，各层维护者在同一批同步路由、引用、状态和索引，最后从一级重新走到改动落点。三级以内的细分用章节表示。

## 二、正文、更新日志和备份

| 内容 | 写入规则 | 谁写 |
|---|---|---|
| 正典 | `verbatim`。保留有效原文，按已批准的改动替换准确位置 | 有明确授权的维护者 |
| 状态 | `supersede`。覆盖对应状态，以最新记录为准 | 该记录的维护者 |
| 知识 | `accumulate`。新证据归到相关条目，处理冲突和过期结论 | 授权范围内的维护者 |

每个受管文件有一个固定位置的更新日志。项目已有映射时沿用。采用 `logRoot` 时，日志路径为 `<logRoot>/<受管文件相对路径>.md`。每批记日期或版本、改动位置、原因、影响和验证或来源定位。正文只写当前有效内容。接手时只读相关文件所需批次。日志在同一文件记录自身的维护，备份和临时验证输出不再生成日志。

改已有文件先确认当前版本，按项目的固定映射保留一份紧邻本批之前的备份。先写暂存备份、校验内容，再覆盖上一份。同批重试沿用本批原备份，无内容变化不写，首次建档从首条日志开始。恢复前检查当前版本，遇到后来修改时只撤销本批差异。更新日志也按相同规则保留一份改前备份。

在 DSH 受控模式中，`building_loop_file` 的 `write` 执行授权检查和滚动备份，`history` 查看已授权文件的近期日志。机器索引校验可由获授权的运行者在 PowerShell 7 中执行并提交结果。

## 三、机器索引

`INDEX.json` 可检查关键文件与日志是否齐全。只登记需要导航或复查的文件，其他受管文件仍各有固定日志和备份。`logRoot` 是 `project-index/1` 的可选扩展，旧索引可继续读取并按项目约定补登记。

```json
{
  "spec": "project-index/1",
  "project": "<项目名>",
  "root": "<项目根，绝对或相对索引文件所在目录>",
  "logRoot": "<相对项目根的日志目录，可选>",
  "generatedAt": "<ISO 8601>",
  "entries": [
    {
      "path": "<相对 root 的文件路径>",
      "tier": 1,
      "rule": "verbatim",
      "route": "read-first",
      "sha256": "<64 位小写十六进制>",
      "bytes": 12345,
      "updatedAt": "<ISO 8601>"
    }
  ]
}
```

- 路径用相对于 `root` 的普通文件路径，禁止父目录段、绝对路径、链接和重解析点。同一文件登记一次。
- `tier` 为 `1`、`2`、`3`，`rule` 为第二节三类之一。`route` 用 `read-first`（给正文）、`on-request`（只给路径）、`not-at-start`（进场不列）。必读文件控制在真正影响开工的范围。
- `sha256` 是对账基准。大小和更新时间给人参考，`generatedAt` 是最近一次实际重建的时间。

有机器索引时，用 PowerShell 7 执行同目录 `check.ps1 -Index <索引文件> -ExpectedRoot <任务单授权的项目根>`。默认只读，检查登记文件的哈希和日志存在性。出现不一致先查看现文，核对是否有漏同步。索引维护者确认后才用 `-Rebuild` 更新，以同目录固定的 `<索引文件>.bak` 保存上一版。缺件或缺日志时拒绝重建。哈希能对账，文件归属、内容与来源由维护者或验收方核实。

## 四、接手和同步

新会话、恢复或压缩后，先读一级总纲和最新交接，再定位任务对应的二级索引。有机器索引时查看变更清单，沿路打开所需三级正文和相关日志。可复用已确认未变的定位。尚未读过的必读文件仍要打开。

进场是只读。工作单元交接时在既有状态文件记录任务号、有效版本、最后完成的动作、未决项和下一步。只把执行所需的上下文传给接手者。

分块、工作单元和下游任务继承父范围时只能收窄。放宽前取得明确授权。派单和验收遵循 `dispatch-protocol`。回执给出被改文件、日志、回滚和新的 SHA-256。各层维护者在同一批同步上层链接和索引，验收方从一级沿链接回查改动，再核对证据。
