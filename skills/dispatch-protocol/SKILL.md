# building-loop 派单协议

任务单、台账和回执是跨会话交接依据。先从项目 `AGENTS.md`、可选的根 `DISPATCH.md` 或任务单确认有效的记录路径、角色、权限和文件落点。按 `project-index` 找一级总纲、所需二级索引和三级正文。

## 一、定角色和范围

| 角色 | 负责 | 权限边界 |
|---|---|---|
| 总控／派单方 | 看一级全貌和进度，定目标、依赖、优先级与验收标准。维护指定中央文件，分派和收回任务 | 根据任务单、台账、回执和核验结论决策。用户明确授权后，才以独立工作单元承担正文调查或修改 |
| 执行方 | 在任务单范围内调查、实现、自验，交回执并同步自己管的文件 | 继续委派需要任务单授权。发现范围外问题，把位置、影响和需要的权限反馈给总控 |
| 核验／验收方 | 核原始出处、产物、验收标准和范围。判定通过、退回或证据不足 | 只读核验所需材料。补查和修正交原执行方。执行方的自验不能签作独立验收 |

单一小任务、串行步骤可由被授权的当前会话作为执行方直接做。总控兼任执行需用户明确授权，两种职责各自记在对应工作单元。重要事实查询或来源核验时，按[证据核验约定](references/evidence.md)给断言定位。

开工、改范围、重试、发起外部动作或恢复前，逐项确认目标、交付、范围、验收和本次权限。查现文能消除的疑问先查。会改变产物、范围或副作用的歧义先问用户，清楚的部分可以继续。涉及修改时先确认原版本、目标文件日志和有效的滚动备份。

## 二、派发和续做

同会话适合一个小单元或依赖明确的串行步骤。独立块可派子代理或工作流，跨时间、权限隔离的工作用落盘任务单交接。并发按宿主报告的容量。容量不明时，一次派一个并等回执。容量拒绝后先核对已接单的单元，再等槽位或按授权处理未接单部分。

**同一分块、同一角色、权限相符优先找原会话。** 在台账记分块、角色、所属父会话、子会话引用和任务号。续派前从台账定位，用宿主现有子代理控制确认可达性和执行状态。DSH 兼容基线下，父会话用 `list_agents` 确认直接子会话，再用 `send_message` 的 `agent_id` 向原会话发任务号、更新范围和变化文件。其他版本按当前工具声明核对参数和权限。忙的会话等本单元交付后再分派，回执才表示交付。

原会话确实不可恢复、外部载具只支持单次调用、权限或职责改变、或需要隔离输入的独立复核时，记录原因并按授权新开。新会话读同一份任务单和最后检查点。同一写任务同一时刻只有一个负责人。切换前确认原执行已结束或明确移交，重复回执用任务号、修订版和已有落盘证据对账。

## 三、工作单元状态

```text
draft → issued → claimed → delivered → accepted → closed
                    │          │
                    │          └── rejected → claimed 或 issued
                    └── blocked → claimed 或 issued

已改动的单元完成授权回滚后 → rolled_back
```

- 总控签发 `issued`，执行方认领和提交 `delivered` 或 `blocked`，验收方填写验收结论。状态写进同一台账。
- `blocked` 回执记原因、解阻负责人、能判断的恢复条件、最后成功检查点和已经产生的改动。只暂停该单元，有依赖的等，独立的照常推进。条件有证据后，原负责人、范围都匹配则回到 `claimed` 从检查点继续。改任务单或换人则重新签发 `issued`。
- 执行问题退原执行方修正，回到 `claimed`。任务单本身有误，修订并重新签发。重试前先检查已完成的写入和证据，防止重复执行。出现不确定的部分明确标记。
- `accepted` 附检查结果路径。关单前确认改动、日志、上层路由和进度完成同步。失败只回滚本单元，恢复前核对现文是否被别人修改过。

## 四、任务单

一份任务单对应一个能独立验收的工作单元。把下面信息写实，指到有效文件版本和位置，供接单方按需读取。

| 节 | 必填信息 |
|---|---|
| 1. 标题与编号 | 任务号、修订版、一句话目标、台账路径 |
| 2. 影响与类型 | 高影响或一般，修改或只读，产出预算和依赖 |
| 3. 执行说明 | 执行角色、输入与现行依据，是否允许再委派 |
| 4. 工作拆分 | 单元和交付落点，大小超出可独立验收范围时拆开 |
| 5. 具体要求 | 文件与锚点、预期效果和理由。新增归到原章节，精确改文时给出预期差异 |
| 6. 验收标准 | 可执行项给命令、参数、预期和输出路径。描述性项给可判定口径及无法脚本化的理由 |
| 7. 自检 | 哪些事实需查证，哪些失败或反例需要验证，交付前核对项 |
| 8. 范围 | 允许读、写和调用的目录、文件或服务，单元范围只能收窄。除非任务单明确授权，禁止从项目根递归扫描 |
| 9. 回滚 | 修改类给改前版本、固定备份位置与恢复方法。只读类明确只读 |

确定性检查可重跑并比对。模型、网络和时间相关检查记录输入、命令、版本、时点和实际结果，按事先约定的口径验收。复现条件齐全只表示可追查。选定台账路径需要项目授权。任务落点与权限不明确时，先问影响本单元的决定。

## 五、回执和台账

回执记录任务号和修订版、执行方及会话引用、提交状态、变更位置、实际验收结果与证据路径、逐文件日志和回滚点。研究或数据类产物给断言和出处的对应关系。把事实、推测、未验证项分别标清，较长输出指向落盘记录。阻塞或退回时按第三节记录责任和下一步。

一行一个工作单元，沿用项目指定的文件和字段，在原位置更新。

| 任务号／修订版 | 分块与角色 | 状态 | 负责人／会话引用 | 产物与证据 | 回滚点 | 阻塞条件／下一步 | 更新时间 |
|---|---|---|---|---|---|---|---|

工作单元可跨多个回合。输出截断后的续轮从台账和最后检查点恢复同一单元。未完成部分继续留在原单元。每交完一件再开自己负责的下一件。

## 六、验收和回复

执行方交付前重读原要求和当前文件，复跑全部适用的可执行检查。追到关键原因和边界，按领域视角核对反例、反对证据、遗漏和可行替代。无法验证的地方标清范围和原因。

验收方用原始证据与事先设定的判据逐项检查。每批选择至少一个重要样本复跑确定性检查，核对产物、证据、回滚和范围。样本由验收方或随机方式选取。项目有人工签字要求时保留人工关口。高影响或不可逆交付追加异构复核，用独立工具推导关键数字，或用不同来源的模型独立查原证据。重复调用同一来源的模型不能算异构复核。受限于权限、材料或工具时，写出未通过的验收项和当前状态。

已有抽样信用记录的项目可沿用。默认只记录抽样通过率。明确启用全量重审时，连续两批抽样失败，对当批该执行方的全部单元重审。

回复先说完成和验收到了哪一步，再分别给事实和证据、推测与未确认项。最后用用户能核对的具体例子、数字或大白话说明结果。
