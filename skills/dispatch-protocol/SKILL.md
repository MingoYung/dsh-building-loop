# building-loop协议 v1

> **定位**：本件＝**building-loop**（preset `building-loop`）的**机制正本**。模式层只承载**约束**——`cordis.patch.yml` 里 `preset-building-loop` 的 persona 铁律 1–11；**本件承载机制**——任务单／回执／状态机／记录。
> **零硬编码**：一切可变项写成 `<占位符>`。**禁**出现任何具体项目名、项目路径、项目角色名、项目编号体系——那些由**项目自己的** `AGENTS.md` 与可选的根 `DISPATCH.md`（见 §六）提供。
> **单一正本**：模板只在本件写全；persona 只留指针，**不复制正文**（禁多副本漂移）。

---

## §一 三个角色

| 角色 | 谁 | 职责 | 红线 |
|---|---|---|---|
| **派单方 dispatcher** | 用户／协调会话 | 起草并签发任务单；定验收标准；抽样验收 | 禁把验收标准的起草权让给执行方（＝自证） |
| **执行方 executor** | 接单会话／子代理／工作流 | 按任务单干活；跑完全部可执行检查；交回执 | 禁越范围；发现问题**报告，不顺手改** |
| **验收方 acceptor** | 派单方，或派单方指定的**异构**来源 | 抽样重跑确定性检查；判定通过／退回 | 禁只看陈述放行 |

**同一会话可兼任多角**，但**「执行」与「验收」不得同为一次自证**——执行方不能给自己的交付签字（铁律 6／9）。

**三种投递形态**（同一个协议，不同载体）：

| 形态 | 载具 | 适用 |
|---|---|---|
| **同会话** | 直接下任务 | 一步就能干完的小活 |
| **子代理／工作流** | `subagent` / `workflow` 工具 | 可并行、可隔离的独立块 |
| **跨会话** | 任务单**落盘**，另一会话读文件接单 | 需要独立上下文、独立权限、或跨时间的活 |

跨会话时**文件即唯一交接面**：任务单与记录落盘，回执落盘；**禁靠会话记忆传递**。

**派遣并发上限（硬闸门）**：本模式装有**并发闸门**——**同时在飞**的子代理数按**当前默认模型的档位**封顶。超限时 `subagent` / `subagent_fork` / `workflow` 的调用会被**当场拒绝**（返回拒绝理由，**不排队、不等待**）。

- **档位数以闸门的拒绝理由为准**——本件不写死数字；拿不准就**先派一个**，别一上来铺开一批。
- **被拒绝时不重试同一批**：等任一个子代理结束再派下一个，或把该步改为**本回合自己完成**。
- 档位是 **DSH 侧机制**（按模型能力分档，切模型自动换档），与具体项目无关。

## §二 工作单元状态机

```
draft(起草) → issued(已派) → claimed(已接单) → delivered(已交付)
                                   ↑                    │
                                   │        ┌───────────┴───────────┐
                                   │        ▼                       ▼
                                   └── rejected(退回)          accepted(验收通过)
                                                                    │
                                                              closed(关闭)

   任意态 ──回滚──> rolled_back(已回滚)
```

**硬规则**：

1. **一个工作单元同一时刻只有一个 owner**；换人＝退回 `issued` 再 `claimed`。
2. **退回只退到 `claimed`**（干得不对），或 `issued`（任务单本身写错了）。**禁连带邻居**——单件失败只回滚本件（铁律 8）。
3. **`accepted` 必须附检查输出的落盘路径**；没有路径＝**不得**置 `accepted`。
4. **状态只写记录**，不靠会话记忆；跨会话续做＝**读记录**恢复现场。
5. **一个单元一个回滚点**；没有回滚点的修改类单元**不得**离开 `claimed`。

## §三 任务单（task slip）

**九节，按序，缺节即不合格。** 一个执行方一份，**自包含**——执行方不读别的文件也能干活。

| # | 节 | 必写 | 内容 |
|---|---|---|---|
| 1 | **标题＋编号** | ✅ | `<批次号> <批名>`；一行说清这批干什么；**记录路径**写在这里 |
| 2 | **头部标注** | ✅ | 影响面 `<高影响／一般>`；性质 `<修改类／只读类>`；验收主体 `<可执行／描述性>`；**产出预算** `<小／中／大>`（超预算＝**在 §4 再拆一层**，见 §九） |
| 3 | **执行说明** | ✅ | 你是谁、干什么、**干完回什么格式**（见 §四） |
| 4 | **拆分** | ✅ | 拆几块／各块归谁／各块产出落点 |
| 5 | **条文（逐条）** | ✅ | 每条＝**位置**（`<文件:锚点>`）＋**改成什么**（旧→新 **逐字**）＋**为什么**；**禁尾追加，一律精准插入** |
| 6 | **验收标准** | ✅ | **两类分写**：`[A*]` 可执行检查（命令＋预期输出＋档位＋输出落盘路径）／`[B*]` 描述性标准（**须写不可执行的理由**） |
| 7 | **自检清单** | ✅ | 开工前／交付前逐条勾（见 §五） |
| 8 | **范围条款** | ✅ | **逐个显式列出**允许扫描的目录 ＋ **禁从项目根递归** |
| 9 | **回滚点** | 修改类必写 | 备份件路径＋恢复命令；只读类**须写明「本批只读」** |

**档位（`[A*]` 每条必标）**：
- **确定性**——同输入必同输出（脚本对账／行数／SHA／计数）。
- **非确定性**——依赖模型／网络／时间。判 **「过程可复现」**（命令＋参数＋时点＋版本四项齐全即算过），**不判「重跑一致」**。

**占比**：`[A*]` 占比过低 ＝ 任务单不合格，验收方可**直接退回重写**。
**起草权**：验收标准由**派单方**起草；执行方**可提议增删、无删改权**。

## §四 回执（receipt）

```
【回执】<批次号> / <单元号>      状态：<delivered | rejected | blocked>
一、位置 → 改动 → 实测证据
    - <文件:行号>：<旧> → <新>
    - 证据：<命令> ⇒ <关键输出行>
二、检查输出
    - [A1] <通过／失败>   输出：<路径>   （只引路径，不粘大段输出）
三、未验证项
    - <明说什么没验、为什么>
四、回滚点
    - <路径>｜恢复：<命令>
五、遗留／发现
    - <范围外的问题：报告，不顺手改>
```

**禁用**「已完成／已确认／应该没问题」代替证据。
**「我做了什么」与「我验证了什么」分开写**；没验证的就明说没验证。

## §五 自检清单

**开工前**：读全文（含范围条款与回滚点）｜确认允许扫描的目录、**不从项目根递归**｜修改类：回滚点**实测可访问**｜按当前步骤装填技能｜**要派出子代理前**确认并发档位（见 §一「派遣并发上限」）。

**交付前**：跑完全部 `[A*]` 并落盘输出｜回执**只引路径**｜格式＝位置＋改动＋实测证据｜范围外**没碰**、发现的问题**报告不改**。

## §六 记录（ledger）与项目侧挂接

**记录＝状态的唯一事实源。** 一行一个工作单元：

| id | 状态 | owner | 产物（路径） | 证据（路径） | 回滚点 | 更新时间 |
|---|---|---|---|---|---|---|

- **记录路径由任务单 §1 指定**（项目可自定）。
- **项目未指定时，派单方必须先问**——**不得擅自新建目录或文件**（受铁律 4 的范围条款约束）。

**项目侧挂接（可选、零耦合）**：项目可在其**根**放一份 `DISPATCH.md`。本模式会把该文件**自动注入**会话（`agent-instructions.instructionFileCandidates` 已含 `DISPATCH.md`），供项目绑定**它自己的**流程名、层级、编号体系、记录位置。

> **本模式对该文件的内容不做任何规定，也不引用任何项目内容。** 有则自动生效，无则本件即为全部。

## §七 抽样验收（治「全体一致地错」）

- **每批验收后抽 ≥1 件深审**；样本由**派单方指定**或**物理随机**（如产物清单的随机行号）。**禁执行方自荐样本**——选择偏差即腐败起点。
- **快审三项**（人的注意力预算约三分钟）：`a` 证据路径**是否真存在** → `b` 关键数字**是否对得上** → `c` 范围外**有没有被动过**。`a` 可脚本代劳；`b`／`c` **必须人亲手**。
- **深审四要素**：原始命令**重跑一致**／产物与声称**一致**／回滚点**可用**／越界**为零**。
- **信用分**：抽样通过率计入该执行方**当批信用分**；**连续两批抽样失败 → 该执行方当批全部重审**。
  - **软启动**：**先记录、先观察**，暂不触发全批重审；除非派单方当批明示启用。

## §八 异构复核

**高影响或不可逆**的交付：验收前加一道**异构**验证——换**不同出身**的模型复核，或**用确定性工具独立推导关键数字**。

- **判据**：**同门再跑一遍不算异构**。
- 不指定具体模型／工具（零硬编码）；**「高影响／非确定」的判定权在派单方**，拿不准**按保守算**。

---

## §九 分批发货（一个回合一件）

**一个工作单元 ＝ 一个回合的交付。** 不要把几个单元铺在同一轮里——铺开的结果通常是几件半成品，而不是一件完成品（persona 铁律 11）。

- **交付顺序**：一件**干完 → 自验 → 回执**，再开下一件。中途发现别件更急，**先把本件回执掉**，再说明换序理由。
- **撞上输出上限时**：
  - **停在单元边界**——宁可本件只做了一部分而**明说欠什么**，也不要写到一半停住、把它当交付。
  - **照常写回执**，尤其「未验证项」与「遗留」两段；不要因为被截断就省掉回执。
  - 本模式会**自动排下一轮续写**（有连续次数上限）。**续写承接的是同一件**——不是开新单元的理由，也不是免回执的理由。
- **大产物的正确切法**：按**单元**切（一个文件 / 一批小修 / 一段分析），**不按输出长度切**。每一块都要能**独立验收**。
- **任务单侧**：产出预算 `<小／中／大>` 超标 ⇒ 在 §4 拆分里**再拆一层**，不要指望执行方一轮写完。
